## 1. 通用要求

| 项 | 要求 |
| --- | --- |
| 编码 | UTF-8（无 BOM） |
| 换行 | LF；**根目录没有 `.gitattributes`**，实际靠 `frontend/.gitattributes` 与 `backend/.gitattributes` 各自约束 |
| 缩进 | 2 空格（前端 / worker）；后端 4 空格（Java 默认） |
| 行宽 | `.editorconfig` 建议 `max_line_length = 100`（**只有 `frontend/.editorconfig`，后端无该文件**） |
| 尾随空格 | 禁止 |
| 语言 | 前端纯 JavaScript（无 TypeScript）；worker 纯 ESM JavaScript（`.mjs`）；后端 Java 17 |
| 命名语言 | 代码标识符用英文；注释与文档用中文 |
| 现状与规划 | 未完成的能力必须在注释/文档中标注「规划 / 待开发」 |

## 2. 前端编码规范

### 2.1 语法

| 规范 | 要求 |
| --- | --- |
| 组件写法 | 一律 `<script setup>`（Composition API） |
| 组件顺序 | `<script setup>` → `<template>` → `<style scoped>` |
| 变量声明 | 优先 `const`，需要重新赋值才用 `let`，禁用 `var` |
| 比较 | 使用 `===` / `!==`，**禁止** `==` / `!=` |
| 异步 | `async/await` + `try/catch`，禁止裸 `Promise.then` 链式忽略错误 |
| Props / Emits | 使用 `defineProps` / `defineEmits`；双向绑定用 `defineModel` |
| 模板 | 禁止在模板中写复杂表达式，逻辑放 `<script setup>` |
| 调试残留 | 提交前清除 `console.log` / 调试用写死数据 |

### 2.2 命名

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 组件文件 | 多单词 **PascalCase** | `LoginForm.vue`、`SpaceGridView.vue` |
| 页面文件 | PascalCase，以 `View.vue` 结尾 | `KnowledgeBaseView.vue` |
| 组合式函数 | `use` + PascalCase | `useSmoothScroll.js` |
| 变量 / 函数 | camelCase | `currentSlide`、`setSlides` |
| 常量 | UPPER_SNAKE_CASE | `CHAT_API`、`MEETING_REST_API`、`PICKABLE_SELECTOR` |
| props | camelCase | `documentName`、`spaceId` |
| emits | **kebab-case** | `login-success`、`open-space`、`delete-document`（待整改例外：`views/ppt/components/ai/AiRemarkBatchDialog.vue` 用 `retryFailed`） |
| Pinia store id | kebab-case | `"ppt-slides"`、`"ppt-screen"`、`"meeting"` |
| 路由 name | kebab-case | `"system-home"`、`"doc-template"` |
| 测试文件 | 前端 `frontend/tests/{行为}.test.js`、worker `digital-human-worker/test/{模块}.test.mjs`；同一行为的多组用例用 `{行为}.{限定}.test.js`（如 `run-state.iterations.test.js`），复现历史缺陷的加 `repro-` 前缀 | `attendees.test.js`、`audio.test.mjs` |

### 2.3 导入

- 跨目录导入统一使用 `@/` 别名（`@` → `frontend/src`，见 `vite.config.js` / `jsconfig.json`）。

  ```js
  import service from "@/api/index";
  import { getToken } from "@/utils/auth";
  ```

- 同一目录内可用 `./`；**禁止** `../../` 这类跨层级相对路径。
- 现状说明：仍有 **15 处** `../../` 跨层级相对导入待收敛（集中在 `views/ppt/components/{screen,thumbnail,element}/**` 与 `views/guides/{HomeView,DocsView}.vue`），`src/router/index.js` 的 `../views/...` 与 `src/api/*.js` 的 `./index` 属同目录/单层，可保留。

### 2.4 注释

- 对外导出的接口函数建议写 JSDoc 契约（现有 `api/doctemplate.js`、`api/homework.js` 已采用）。
- 复杂逻辑（算法、兼容性处理、第三方库 workaround）必须写注释说明**为什么**，而非复述代码。
- 现状 / 规划、临时方案、待整改点用 `// TODO:` / `// 规划:` 标注。

## 3. 后端编码规范

### 3.1 包与命名

| 对象 | 规则 |
| --- | --- |
| 包名 | `org.example.backend.*`，全小写。**已知唯一例外**：`tb-module-workflow` 整模块包根为 `org.example.textflow.*`（42 个主源码类），新增后端模块不得再引入第二个包根 |
| 模块前缀 | 框架 `framework.*`；业务 `module.{模块名}.*` |
| 类 | PascalCase（`KbDocumentServiceImpl`、`DocTemplateController`） |
| 方法 / 变量 | camelCase |
| 常量 | UPPER_SNAKE_CASE |
| DO | 与表名对应的 PascalCase + `DO` 后缀；字段 camelCase，映射下划线列（普通 POJO + Lombok，**不继承 `BaseDO`**） |
| DTO / VO | `XxxReqVO` / `XxxRespVO` / `XxxSaveReqVO` |
| Mapper | `XxxMapper`（接口，无 XML，方法上写 `@Select` / `@Insert` / `@Update`） |

### 3.2 分层与依赖

- 分层：`controller` → `service`（接口 + `service/Impl`）→ `mapper` → `model`(DO) / `model/vo`。
- **依赖单向**，禁止反向依赖；`Controller` 不得直接调用 `Mapper`。
- 跨模块调用只依赖对方的 `service` / `biz` 接口，禁止直接依赖实现类与内部 DO。

### 3.3 语言与工具

| 规范 | 要求 |
| --- | --- |
| Lombok | 一律使用（`@Data`、`@Accessors(chain = true)` 等），禁止手写 getter/setter/toString |
| 数据访问 | **业务 Mapper 用 MyBatis 注解 SQL**（`@Select` / `@Insert` / `@Update`，必要时 `<script>` 动态 SQL）+ `@Options(useGeneratedKeys = true)` 回填主键；**禁止新增 MyBatis XML**。框架层的 MyBatis Plus（`BaseMapperX` + `Wrappers`）目前未被任何业务模块依赖，选它需先把 starter 接进模块 |
| 例外 | `tb-module-workflow` 用 `spring-boot-starter-jdbc` + `JdbcTemplate`（`repository/` 下手写 INSERT/SELECT），并在类注释里明确「不引入 MyBatis」 |
| 校验 | 入参用 DTO/VO + `@Valid` / 校验注解，服务端必须校验 |
| 异常 | 业务异常抛 `ServiceException`（经 `ServiceExceptionUtil`）；禁止吞异常、禁止 `e.printStackTrace()` |
| 返回 | Controller 返回 `CommonResult<T>`；仅两处例外：`POST /chat`（`SseEmitter`）、`GET /workflow/text`（`void`，联调桩） |
| 时间 | 统一走 `tb-common` 的 `DateUtils`，禁止散落的 `new Date()` 格式化。**现状**：业务模块普遍直接用 `LocalDateTime.now()`，`DateUtils` 仅 `tb-module-test` 在用 |
| 配置 | 使用 `@ConfigurationProperties` 绑定（如 `SecurityProperties`、`DocTemplateProperties`、`MeetingProperties`、`DigitalHumanProperties`），禁止散落 `@Value`。**现状**：仍有 3 处 `@Value`（见 §3.4） |
| 注释 | 公共类与对外方法写 Javadoc（中文），说明职责与关键约束 |

### 3.4 待整改（现状与规范不一致）

| 位置 | 现状 | 规范要求 |
| --- | --- | --- |
| `tb-module-test2/.../controller/PptxPage.java` | 普通 VO 放在 `controller` 包 | 移入 `model/vo` |
| `tb-module-infra/.../service/MinioFileStorageService.java` | 实现类直接放在 `service/` | 与其它模块一致，放入 `service/Impl/` |
| `tb-module-test2/Test2Controller` | 硬编码绝对路径读取本地 pptx（验证性代码） | 移入配置或删除，禁止硬编码本机路径 |
| `tb-module-test/.../OAuth2TokenServiceImpl` | 两处 `@Value("${test.oauth2.*-validity-seconds:默认}")` | 收敛为 `@ConfigurationProperties` 绑定类 |
| `tb-module-homework/.../HomeworkController.grade` | 用 `System.out.println(reqVO)` 打请求体 | 改用日志框架 |
| `sql/newsql/public.sql` | 全量导出脚本内含 `DROP TABLE` | 只作参考，禁止当作迁移脚本执行 |

## 4. 检查与门禁

| 范围 | 命令 | 说明 |
| --- | --- | --- |
| 前端 lint | `npm run lint` | 顺序执行 `oxlint . --fix` 与 `eslint . --fix --cache`（`run-s`，来自 `npm-run-all2`） |
| 前端测试 | `npm test` | `node --test "tests/*.test.js"`，当前 16 个用例（见 [11](./11-测试规范.md)） |
| worker | `npm test` / `npm start` | `node --test "test/*.test.mjs"` / `node src/index.mjs`（在 `digital-human-worker/` 下执行） |
| 后端 | `./mvnw clean install` | 全模块构建；目前在 CI 前作为人工门禁 |
| 后端测试 | `./mvnw test` | 已有 **2 个模块 8 个测试类**（`tb-module-lecture` 6 个、`tb-module-workflow` 2 个），见 [11-测试规范.md](./11-测试规范.md) |

- 提交前必须本地跑通上述命令，不得以「稍后修」为由提交带 lint 报错的代码。
- 前端 `.oxlintrc.json` 将 `categories.correctness` 设为 `error`；ESLint 使用 flat config（`eslint.config.js`）。
- **工具强制范围要如实看待**：`==` / `!=` 的禁止、组件名多单词、`@/` 别名统一都**没有**被 ESLint 全量拦截（只启 `js.recommended` + `vue essential`，且对 `views/ppt/index.vue` 等显式放行），因此靠 review 与本文约束，不靠 lint。

## 5. 数字人 worker 编码规范 — `digital-human-worker/`

| 项 | 要求 |
| --- | --- |
| 模块系统 | `"type": "module"`，源码与测试一律 `.mjs` 扩展名 |
| 依赖 | 只允许 `@livekit/rtc-node`；不引 HTTP 框架，`node:http` 手写路由（见 `src/server.mjs`） |
| 入口配置 | 环境变量在 `src/index.mjs` 的 `loadDotEnv()` 里从 `../.env` 读取，**只填已存在的进程环境不覆盖**；模板见 `digital-human-worker/.env.example` |
| 安全默认值 | `WORKER_HOST` 默认 `127.0.0.1`；`AGENT_SHARED_SECRET` 为空时除 `/healthz` 外全部 503，不得改成放行 |
| 音频帧 | 送给 LiveKit 的每帧必须**独占一个 `ArrayBuffer`**（不能复用切片底层缓冲），实现集中在 `src/audio.mjs`；违反表现为电音/错位字节（提交 `c1f2337`） |
| 测试 | `test/*.test.mjs` 用 `node:test` + `node:assert/strict`，不起真实 LiveKit 服务 |
| lint | **当前无 lint 配置**，改动时手工对齐现有 `.mjs` 风格：2 空格缩进、单引号、行尾不写分号 |
