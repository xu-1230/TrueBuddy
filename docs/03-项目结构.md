### 2.2 模块职责与依赖

| 模块 | 职责 | 关键依赖 |
| --- | --- | --- |
| `tb-dependencies` | 统一版本管理 BOM（Spring Boot / Spring AI / MyBatis Plus / Hutool / Guava） | 无 parent |
| `tb-common` | `CommonResult` / `PageResult` / `ErrorCode` / `ServiceException` / `UserTypeEnum` / 工具类 | Lombok、Hutool |
| `tb-spring-boot-starter-web` | `GlobalExceptionHandler`、`WebFrameworkUtils`、`WebAutoConfiguration` | spring-boot-starter-web、`tb-common` |
| `tb-spring-boot-starter-mybatis` | `BaseDO`、`BaseMapperX`、`DefaultDBFieldHandler`、分页插件 | mybatis-plus-spring-boot3-starter |
| `tb-spring-boot-starter-security` | `SecurityConfig`、`SecurityAutoConfiguration`、`TokenAuthenticationFilter`、`LoginUser`、`SecurityFrameworkUtils` | `tb-common`、web starter、Spring Security、Guava |
| `tb-module-test` | 连通性接口、登录鉴权、身份校验；自定义 MyBatis JSON TypeHandler | security starter、PostgreSQL、MyBatis |
| `tb-module-test2` | pptx / PDF / jsoup / markdown 文档解析验证 | Spring AI document reader、POI |
| `tb-module-knowledgebase` | 知识库空间、文档、分片、向量化（pgvector） | `tb-module-infra`、pgvector starter、OpenAI starter、阿里云文档智能 SDK |
| `tb-module-infra` | 通用文件上传与元数据（`infra_file`），MinIO 存储 | MinIO 8.5.10 |
| `tb-module-doctemplate` | 模板解析 → LLM 规划改写 → MCP 落盘 → 自检修复 | `tb-module-infra`、`tb-module-knowledgebase`、MCP Client、OpenAI starter |
| `tb-server` | 启动入口，聚合全部业务模块并提供 `application.yml` | 全部业务模块 + `spring-boot-maven-plugin` |

> 业务模块保持**单模块**（不拆分 `api` / `biz` 子模块）；`-biz` 前缀仅用于框架 starter 命名的历史惯例。

### 2.3 包结构

包根统一为 `org.example.backend`：

```
org.example.backend/
├── framework/
│   ├── common/            # pojo / exception / enums / util / biz
│   ├── web/               # config / core.handler / core.util

```

### 2.4 分层职责

| 层 | 职责 | 位置 | 约束 |
| --- | --- | --- | --- |
| Controller | 接收请求、参数校验、返回 `CommonResult<T>` | `module/{m}/controller/` | 不写业务逻辑、不直接调 Mapper |
| Service | 业务逻辑、事务边界（接口 + 实现分离） | `module/{m}/service/`、`service/Impl/` | 对外暴露接口 |
| Mapper | 数据访问（继承 `BaseMapperX`） | `module/{m}/mapper/` | 无 XML，使用 `Wrappers` |
| DO | 数据库实体（继承 `BaseDO`） | `module/{m}/model/` | 不得出现在接口入参/返回值 |
| VO / DTO | 接口出入参 | `module/{m}/model/vo/` | 命名 `XxxReqVO` / `XxxRespVO` |
| Enums | 模块错误码 | `module/{m}/enums/` | 继承 `ErrorCode` 形式 |
| Config | 模块级配置与 `@ConfigurationProperties` | `module/{m}/config/` | 敏感项走环境变量 |

**依赖方向**：`Controller → Service → Mapper → DO`，严格单向。

> 模块特例（现有实现，非通用约定）：
> - `knowledgebase` 额外有 `service/parse/`（`DocumentParseGateway` + `ParseGatewayConfiguration` + `ParseTaskStatus` + `parse/docmind/DocMindParseGateway`）与 `service/chunk/`（`DocumentChunkService` + `AiDocumentChunkService`），分别承载文档解析与 AI 语义分片。
> - `doctemplate` 额外有 `prompt/AiPromptConstants`、`service/DocxMcpGateway`（MCP 网关接口 + `Impl`）。
> - `test` 额外有 `mybatis/handler/`（JSON TypeHandler）。

### 2.5 数据库脚本 — `sql/`

| 文件 | 作用 |
| --- | --- |
| `init.sql` | 数据库初始化：`uuid-ossp` + `vector` 扩展 |
| `vector_store.sql` | 向量存储扩展初始化（对齐 Spring AI PgVectorStore：1024 维 / hnsw / cosine） |
| `system_user.sql` · `system_role.sql` · `system_menu.sql` · `system_user_role.sql` · `system_role_menu.sql` | RBAC 五张表 |
| `system_oauth2_access_token.sql` · `system_oauth2_refresh_token.sql` | OAuth2 令牌表 |
| `infra_file.sql` | 文件元数据表 |
| `kb_space.sql` · `kb_document.sql` · `kb_document_parse_block.sql` · `kb_document_chunk.sql` | 知识库四张表：空间 / 文档 / 解析版面块 / 分片 |
| `doc_template.sql` | 文档模板生成任务与结果文件表 |
| `newsql/identity_data.sql` · `newsql/public.sql` | 身份种子数据 / 数据库全量导出（`public.sql` 含 `DROP TABLE`，**仅作参考**） |

### 2.6 知识库数据模型与处理链路

**四张表**：

| 表 | 职责 | 删除策略 |
| --- | --- | --- |
| `kb_space` | 知识库空间 | 软删（`deleted BOOLEAN`） |
| `kb_document` | 文档元数据与处理状态 | 软删（`deleted_at`，`NULL` = 未删除） |
| `kb_document_parse_block` | 解析产物：版面块（块级，含页码 / 页内序号 / 引擎块 ID） | 物理删 |
| `kb_document_chunk` | AI 语义分片（向量化的最小单位，**不携带类型与标题**） | 物理删 |

**处理链路**（`KbDocumentServiceImpl`）：

```
上传(MinIO + infra_file) → 提交 docmind 解析 → 轮询 parse-status
  →[5] 解析产物落库（块级）
  →[6] AI 语义分片（DocumentChunkService）
  → 分片落库 →[4] 待确认 → 用户校对 →[7] 向量化 →[2] 已完成
任一步失败 →[3] 失败
```

**`kb_document.status` 取值**：

| 值 | 含义 | 值 | 含义 |
| --- | --- | --- | --- |
| 0 | 待处理 | 4 | 分片待确认 |
| 1 | 解析中 | 5 | 解析完成待分片 |
| 2 | 已完成（已向量化） | 6 | AI 分片中 |
| 3 | 失败 | 7 | 向量化中 |

> 版面类型属于 `kb_document_parse_block.block_type`（取值开放，不做枚举约束）；分片层不再冗余类型信息。
> AI 分片只让模型输出「块区间」，正文由后端按区间拼接，模型无法改写原文；模型不可用时回退为「一块一分片」。

### 3.3 业务模块目录约定

每个业务模块在 `views/{模块}/` 内**自治**，私有资源就近放置：

| 目录 | 含义 | 现有示例 |
| --- | --- | --- |
| `components/` | 模块内私有组件 | `doctemplate/`、`homework/`、`knowledgebase/`、`ppt/` |
| `mock/` | 演示数据（标注「演示态」） | `homework/mock/grading.js`、`ppt/mock/` |
| `utils/` | 模块内工具函数 | `homework/utils/{export,format,workflows,zip}.js`、`ppt/utils/` |
| `stores/` | 模块独享 Pinia store | `ppt/stores/{slides,screen}.js` |
| `hooks/` | 组合式函数 | `ppt/hooks/` |
| `configs/` | 模块常量配置 | `ppt/configs/` |
| `styles/` | 模块样式 | `ppt/styles/{animation,prosemirror}.css` |

> `views/workflow/` 当前仅 `WorkflowView.vue` + `test/{StartNode,ForNode,FunNode}.vue`，为**示例画布**状态，尚未按上表拆分（见 [01-项目概述.md](./01-项目概述.md) §7）。
