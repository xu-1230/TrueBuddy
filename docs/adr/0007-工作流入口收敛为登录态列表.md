# 工作流入口收敛为登录态列表（废弃 `?workflow_id` 兼容路径）

> 2026-11-17 ｜ 相关：[docs/specs/2026-11-17-工作流入口列表与公有复刻.md](../specs/2026-11-17-工作流入口列表与公有复刻.md)、[docs/doc-workflow.md](../doc-workflow.md)、[docs/doc-api.md](../doc-api.md)、[adr/0006-知识库与工作流归属与共享模型.md](./0006-知识库与工作流归属与共享模型.md)

## 背景

工作流页 `/index/workflow` 长期以「画布」作为模块入口：无 `workflow_id` 时直接渲染默认画布，有 `workflow_id` 时按 query 载入定义。归属共享（ADR 0006）落地后，用户没有「我的工作流列表」可看，公有库只能从画布抽屉进入；同时 `/workflow/**` 在免登录白名单里，匿名可以读写定义类接口。工作流是第一个以「列表 + 详情」形态重构的模块，需要一次把入口地址与登录口径定死。

## 决策

1. **模块入口改为列表**：`/index/workflow` 为「我的工作流 + 公有库」；画布移至 `/index/workflow/:id`；新建为 `/index/workflow/new`。
2. **废弃 `?workflow_id=` 兼容路径**：不做重定向，旧链接落到列表并忽略该参数。新代码只生成路径式地址。
3. **`/index` 整体要求登录**：用户端后台路由在父级声明 `requiresAuth`；`/workflow/**` 移出 `tb.security.permit-all-urls` 白名单，服务端权限边界不再依赖「URL 级免登录 + 服务层兜底」。
4. **公有库入口唯一**：画布内的「公有库」抽屉移除；公有资源只在列表页浏览、打开只读画布或 fork。
5. **内置模板只读可运行**：builtin 在列表单列置顶；画布禁止编辑 / 保存 / 可见性 / 删除 / fork，但允许运行（`own OR builtin` 直跑闸不变）。

## 为什么不是别的

- **保留 `?workflow_id=` 并重定向**：多一条永久兼容路径，与「URL 唯一真相源」冲突；本项目没有外部消费者，旧链接只存在于文档与本仓库，直接切断成本最低。
- **只给工作流三条路由加登录要求**：`/index` 下其它页面（首页、批改、知识库）同样依赖登录态数据，只收口工作流会让匿名边界看起来成立、实际不成立；父级统一收口更可解释。
- **保留画布公有库抽屉**：列表页已经承担发现与 fork，两处维护同一份公有列表会漂移；单入口更简单。
- **内置模板继续可编辑**：后端本就拒绝保存 / 可见性 / fork，前端允许编辑只会制造「改完保存失败」的坏体验。

## 后果

- 旧的 `?workflow_id=` 书签 / 文档链接失效，落到列表；受影响入口（批改页、首页、管理端）在本次同步更新。
- 匿名访问 `/index/*` 一律跳登录；`/workflow/public-list` 的匿名分支从此不可达（Service 保留 null 兜底，不再作为产品能力）。
- `WorkflowVO` 需要补 `visibility` 供列表卡片渲染；新增软删除接口后，已删除工作流的会话 / 执行记录保留，但再用它运行会报「工作流不存在」。
- 画布页从「模块入口」退化为「详情页」，全幅布局只对 `/index/workflow/*` 生效。
