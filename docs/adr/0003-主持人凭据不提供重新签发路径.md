# 主持人凭据不提供重新签发路径

`hostToken` 只在 `POST /meeting/create` 的响应里返回一次，前端按会议号存 `localStorage`（`?meetid=` 可跨标签页恢复）。清了缓存、换了浏览器或换了机器，就永久失去该会议的主持能力，只能重新建会。我们**接受这个不可恢复性**，只做显式提醒（建会成功处高亮可复制的凭据；读取不到时给出「凭据已丢失，请重新建会」的明确文案），不新增任何找回接口。

## 为什么

`/meeting/**` 全量在 `tb.security.permit-all-urls` 白名单里（docs/16 Q8：学生免登录匿名参会），会议内身份只有 `hostToken` / `attendeeToken` 两种 bearer 式凭据。在这种模型下，任何「按 `meetingNo` 重新签发 hostToken」的接口都等价于**任何人枚举会议号即可接管并结束别人的会议**——包括本来就不该出现的 `GET /meeting/list`，它同样会让会议号（即入会地址）被批量枚举。

## 后果

要真正解决"换设备继续主持"，前提是先给会议引入归属（`host_user_id` + 登录态 + 会议号不可公开枚举），那会推翻「免登录匿名会议」的整体模型，必须单独立项讨论，不能夹带在本次修复里。同理，**本期不做历史会议列表接口**——需求被"在线成员"取代后它就是孤儿接口，且在无归属模型前它扩大了会议号的暴露面。
