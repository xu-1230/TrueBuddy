# 自动模式下「页面真相」修订为：页码写入方必须持有推进授权

doc-lecture.md §13 原则 1 是「放映页是页码的唯一权威」。工作项引入自动推进（ai 模式：播完即翻）后这条原样成立就会自相矛盾。本 ADR 修订为：**页码写入方必须持有推进授权；授权来自老师写下的演讲方式（mode）**。

## 决策

1. 'verbatim' 照读模式原原则**原样成立**：放映页是页码唯一权威，工作项只跟随不推进。
2. 'ai' 模式下合法的页码写入方有两个，冲突时**后到者生效**：工作项的确定性 gate（授权来自老师选择的 mode）；老师本人手动翻页（打断权，任何时刻不受损——gate 每次以当前 slideIndex 重算，无隐藏状态）。
3. 模型（LLM）**永远不是页码写入方**：只决定「这一段说什么」，何时翻页由确定性 gate 执行（dsh 铁律：模型判定与执行分离）。
4. advance 必须复用放映页既有翻页语义（execNext：先元素动画后翻页）；直接写 store 的 slideIndex 会绕过动画状态机（animationIndex 残留），是被拒绝的实现。
## 为什么不是别的

- **自动模式只建议不执行（每次翻页等确认）**：等于没有自动推进，且每次确认都是注意力税（与 doc-lecture.md §13「最小注意力占用」公理冲突）。
- **模型输出「该翻页了」信号触发翻页**：不可控（提前翻学生没看清、拖延冷场），且每次翻页多一次模型往返；翻页是确定性事件（音频播完），不需要语义判断。

## 后果

- 老师在 ai 模式下手动翻页 = 立即接管：旧回合作废、新页立即开讲，advance 的缓冲定时器因页码已变自动丢弃。
- 放映页退出放映（ScreenView 卸载）后 advance 无处落地：runner 停在「等待翻页」，由老师手动恢复或停止——工作项不做兜底跳页。
- lesson-start 信号携带 mode，台账里每次「自动推进」都能对回答课方式的选择记录。
