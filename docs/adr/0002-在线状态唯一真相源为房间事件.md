# 在线状态的唯一真相源是 LiveKit 房间事件，参会表删除 online 列

docs/16 Q9 早先只说「`online` 退化为历史」但保留了列，结果它同时被入会闸门（已删，见 ADR-0001）和 `meeting.onlineCount` 读取，两处都在谎报。本次把话讲死：**在线与否只有 LiveKit 房间事件这一个真相源**，前端控制台与会议室的在线人数、在线名单一律由订阅到的 participants 得出；`lecture_meeting` 不再返回 `onlineCount`，`lecture_meeting_attendee` **删掉 `online` 列**，退化为纯台账（`joinTime` / `leaveTime`），新增 `POST /meeting/leave` 写 `leaveTime`。

## 为什么不是别的

- **后端调 ListParticipants 返回在线数**：`detail`/`state` 是 GET，docs/doc-api.md:47 明确 GET 不得有副作用，而把 LiveKit HTTP 塞进这两个读接口只会增加超时面；房间事件本来就已经推给了前端，没有信息缺口需要后端补。
- **保留 `online` 布尔列**：布尔列和 `leaveTime IS NULL` 表达同一件事，两份真相必然漂移。删列后「尚未显式离开」是唯一诚实的表述，它也不再被冒充成「在线」。

## 后果

崩溃、断网、直接关标签页不会写 `leaveTime`，台账里会留下「尚未显式离开」的行——**这是预期的，不得再被任何代码当作在线状态使用**。`markAllOffline` 改名 `markAllLeft`（`SET leave_time = now() WHERE leave_time IS NULL`）。LiveKit 不可用时，前端同时失去在线人数与在线名单，这是接受单一真相源的代价。
