## 1. 安全与配置约束

### 1.1 强制要求

- **敏感信息一律环境变量注入**：数据库凭据、模型 API Key、MinIO 密钥只允许以 `${VAR}` 占位符出现在 `application.yml` 中。
- **禁止硬编码**：源码、配置、脚本、文档中均不得出现真实密钥、口令、Token。
- **不提供弱默认值**：必填变量的 `${VAR}` 写法不写默认值，缺失即启动失败，避免误用。
- `.env` 存放真实凭据且已被 `.gitignore` 忽略；仓库只保留 `.env.example` 模板。
- `docx-mcp` 的 `mcp-servers-config.json` 及后端 MCP 配置**不得内联凭据**，由后端进程环境继承。

## 2. 统一返回与错误码

### 2.1 统一返回

所有后端接口返回 `CommonResult<T>`（位于 `tb-framework/tb-common` 的 `framework.common.pojo`）：

```json
// 成功
{ "code": 0, "message": "", "data": {} }

// 失败
{ "code": 500, "message": "错误描述", "data": null }
```

- `code = 0` 表示成功，`data` 为业务数据；`code != 0` 表示失败，`message` 可直接展示给用户。
- 静态工厂：`CommonResult.success(data)` / `CommonResult.error(code, message)`。
- 分页统一使用 `PageResult<T>`（`list` + `total`）。
- 前端 axios 响应拦截器在 `code === 0` 时透明解包为内层 `data`（见 [05-API规范.md](./05-API规范.md)）。

### 2.2 错误码

常量定义于 `framework.common.exception.enums.GlobalErrorCodeConstants`：

| code | 含义 | code | 含义 |
| --- | --- | --- | --- |
| 0 | 成功 | 429 | 请求过多 |
| 400 | 请求参数错误 | 500 | 系统异常 |
| 401 | 未认证 | 501 | 未实现 |
| 403 | 无权限 | 502 | 系统配置错误 |
| 404 | 资源不存在 | 900 | 重复请求 |
| 405 | 方法不允许 | 901 | 演示模式禁止操作 |
| 423 | 已锁定 | 999 | 未知错误 |

- 业务异常使用 `ServiceException` / `ServerException`，通过 `ServiceExceptionUtil.exception(ErrorCode)` 抛出。
- 全局异常处理 `GlobalExceptionHandler`（`@RestControllerAdvice`）统一转换为 `CommonResult`，**不得向客户端泄漏堆栈**。
- 各模块自定义错误码集中在模块内 `enums/ErrorCodeConstants`。

## 3. 禁止事项

| # | 禁止 | 原因 / 替代方案 |
| --- | --- | --- |
| 1 | 使用 `==` / `!=` | 统一 `===` / `!==`（前端） |
| 2 | 前端跨层级相对路径导入（`../../`） | 使用 `@/` 别名 |
| 3 | 在模板中写复杂表达式 | 逻辑移到 `<script setup>` |
| 4 | 将 `DO` 直接暴露到接口层 | 使用 `ReqVO` / `RespVO` |
| 5 | 手写 SQL 或新增 MyBatis XML | 使用 `Wrappers` 条件构造器 |
| 6 | 硬编码密钥、口令、Token、本机绝对路径 | 环境变量注入 / 配置项 |
| 7 | 在 `src/components/` 之外重复实现同名通用组件 | 先抽取复用（现状 `SquircleButton.vue` 在 doctemplate 与 homework 各有一份，待整改） |
| 8 | 未经标注把「规划」能力当现状使用 | 规划内容必须显式标注 |
| 9 | 提交带 lint 报错的代码 | 先跑 `npm run lint` |
| 10 | 提交 `.env`、`node_modules`、`target`、`dist` | 已被 `.gitignore` 忽略 |

## 4. 跨端对接约定

| 项 | 约定 |
| --- | --- |
| 端口 / 上下文 | 后端 `8086`，`server.servlet.context-path = /api` |
| 前端 baseURL | `/api`（开发经 Vite 代理到 `http://localhost:8086`） |
| 数据格式 | JSON；上传使用 `multipart/form-data`（前端不手设 `Content-Type`） |
| 统一返回 | `CommonResult<T>`，`code = 0` 成功，拦截器自动解包 |
| 认证 | `Authorization: Bearer <token>`；Token 由 `src/utils/auth.js` 基于 js-cookie 管理 |
| 跨域 | **实际未配置可用的 CORS**：`SecurityConfig` 只有 `.cors(withDefaults())`，全仓没有 `CorsConfigurationSource` / `addCorsMappings` / `@CrossOrigin`，因此浏览器跨源请求拿不到允许头。开发期靠 Vite 代理 `/api` 规避；真要跨源部署必须补 Bean |
| 上传上限 | 单文件 `50MB`、单请求 `1024MB`（作业整包靠请求上限放行） |
| 实时通信（工作流） | **SSE**：`POST /chat` 以 `text/event-stream` 推执行事件（读取封装在 `src/utils/workflow-sse.js` 的 `readWorkflowStream`，事件→状态归约在 `views/workflow2/utils/run-state.js`）。**没有轮询兜底**：`workflow-poll.js` 与 `GET /workflow/get_process` 都未落地，终态只认 `conversation.chat.{completed,failed,requires_action}` 帧；`requires_action` 后同一条流继续 |
| 实时通信（模拟会议） | **自托管 LiveKit**（Apache-2.0 SFU，部署在仓库外的 `D:\ctf\livekit`）：`join`/`detail`/`state` 下发 `{ livekitUrl, livekitToken }`，前端 `views/meeting/hooks/useLiveKitRoom.js` 连接房间 —— 屏幕共享走音视频轨、聊天走 DataChannel（RELIABLE）、成员与在线数取自 participant 事件。**后端不参与实时转发**，只签发 JWT（Hutool 手写 HS256）与在结束会议时调 `RoomService/DeleteRoom`。权限（学生 `canPublish=false`）由令牌在服务端强制 |
| 实时通信（数字人，默认关闭） | 后端 `tb-module-lecture` 的 `digital/` 用 DashScope CosyVoice 合成裸 PCM，经 HTTP 推给仓库根的 `digital-human-worker/`（`POST /say`、`POST /sessions`，共享 `TB_AGENT_SHARED_SECRET`），由 worker 用 `@livekit/rtc-node` 发布成房间音频轨；前端只消费音频，`views/meeting/utils/agentAudio.js` 负责播放、`GET /meeting/digital/status` 负责可用性探测。**JVM 侧发不了音频轨**，砍掉 worker 就等于砍掉播报 |
| AI 长请求（PPT 讲稿） | `POST /ppt/speech/optimize` 是**一次请求整篇**：后端按 `tb.lecture.ppt.batch-size` 分批调用模型（每批约十几秒），几十页时整体 1–2 分钟。前端必须 ①按钮 `disabled` + 状态提示（**不谎报分批进度**）②离开页面时 `AbortController.abort()`。注意：**中止只是前端不再等，后端会把当前批次跑完**（无状态接口的固有代价，不为此建任务表） |
| AI 长请求（PPT 讲稿） | `POST /ppt/speech/optimize` 是**一次请求整篇**：后端按 `tb.lecture.ppt.batch-size` 分批调用模型（每批约十几秒），几十页时整体 1–2 分钟。前端必须 ①按钮 `disabled` + 状态提示（**不谎报分批进度**）②离开页面时 `AbortController.abort()`。注意：**中止只是前端不再等，后端会把当前批次跑完**（无状态接口的固有代价，不为此建任务表） |
| 异步放行 | 安全过滤器对 `DispatcherType.ASYNC` 放行（供 SSE 异步派发使用） |
