# 工作流列表卡片对齐知识库（重命名 / 公有私有 / 删除 / 图标尺寸）

日期：2026-11-17 ｜ 模块：`frontend/src/views/workflow2`、`backend/tb-module-workflow`
上游规范：[docs/doc.md](../doc.md)、[docs/doc-conventions.md](../doc-conventions.md) §5
前序：[specs/2026-11-17-工作流入口列表与公有复刻.md](./2026-11-17-工作流入口列表与公有复刻.md)、[adr/0007](../adr/0007-工作流入口收敛为登录态列表.md)
相关：[docs/doc-workflow.md](../doc-workflow.md)、[docs/doc-api.md](../doc-api.md)

## 1. 问题陈述

工作流列表首版只提供了「打开 / 公有私有 / 删除」，与知识库空间卡的操作集合不一致：

- 缺少「重命名」入口；用户改名必须先打开画布、点保存、改名称，路径过长。
- 卡片右上角操作图标为 22px，知识库空间卡为 32px，同一套侧栏页面里视觉密度不一致。
- 「私有」常驻角标在知识库页没有对应物（知识库只在公有时常驻「公有」角标），列表显得更吵。

## 2. 方案概述

- **重命名**：列表卡片增加编辑图标，弹窗只改名称；后端新增 `PUT /workflow/rename`，不要求回传 `schemaJson`（避免列表为了改名而拉取并回写整份画布，产生覆盖风险）。
- **公有私有**：与知识库一致——公开时常驻「公有」角标；私有不再显示角标；切换入口在卡片右上角（本人、非 builtin）。
- **删除**：沿用已落地的 `DELETE /workflow/delete`，只是图标尺寸对齐。
- **图标尺寸**：`.workflow-card__action` 字号对齐 `SpaceCard` 的 32px，操作区 `top/right: 8px`。

## 3. 口径

| # | 决策 | 结论 |
| --- | --- | --- |
| D1 | 重命名接口 | 新增 `PUT /workflow/rename?workflow_id=&name=`；登录必需、仅创建者、builtin 拒绝 |
| D2 | 校验 | 名称 trim 后非空、≤100 字符；返回 `CommonResult<Boolean>` |
| D3 | 重名 | 不强制唯一（与保存对话框一致；fork 副本命名仍由应用层防撞） |
| D4 | 卡片操作 | 本人卡：公有私有切换 / 编辑（重命名）/ 删除；builtin：无操作；公有卡：仅 fork |
| D5 | 角标 | builtin → 「内置」；本人公有 → 「公有」；私有 / 他人公有卡不显示角标（公有区整区即公有，与 SpaceCard 一致） |
| D6 | 图标尺寸 | 32px，与 `SpaceCard` 完全一致；操作区 `top/right: 8px` |
| D7 | 重命名弹窗 | `el-dialog` + 名称输入（`maxlength=100`）；名称未变化时不发请求 |
| D8 | 文档 | 新增本 spec；回写 `doc-api.md` §2.5、`doc-workflow.md` §2.1/§6.3/前端消费方 |

## 4. 验收项

| # | 场景 | 预期 |
| --- | --- | --- |
| AC1 | 我的卡片点编辑图标 | 弹出「重命名工作流」弹窗，输入框回填原名 |
| AC2 | 输入新名称保存 | 卡片名称立即更新；刷新后保持 |
| AC3 | 名称留空 / 超 100 字 | 前端拦截并提示；不发请求 |
| AC4 | 名称未变化 | 关闭弹窗，不发请求 |
| AC5 | 公有卡的编辑入口 | 不显示；只能 fork |
| AC6 | 内置模板的编辑 / 删除 | 不显示；后端同样拒绝 |
| AC7 | 他人尝试重命名 | 后端 403 |
| AC8 | 匿名调用重命名 | 后端 401 |
| AC9 | 图标尺寸 | 卡片右上角三个操作图标与知识库空间卡一致（32px） |
| AC10 | 角标 | 私有卡无角标；本人公有卡「公有」；公有库卡片无角标；builtin「内置」 |

## 6. 明确不做

- 不在列表编辑说明 / 画布内容（仍走画布保存）。
