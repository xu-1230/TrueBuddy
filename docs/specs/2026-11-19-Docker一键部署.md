## 2. 口径与决策

| # | 决策 | 依据 |
| --- | --- | --- |
| 1 | 四服务编排：`db`(pgvector) / `minio` / `backend` / `frontend`(nginx) | 无 Redis/MQ；LiveKit 仍为仓库外可选组件，不纳入本次一键部署 |
| 2 | docx-mcp 与后端进**同一镜像/容器**，通过覆盖 `spring.ai.mcp.client.stdio.servers-configuration` 指向 Linux 路径 | MCP 是 stdio 子进程，`docId` 依赖同一会话进程树 |
| 3 | 后端镜像最终层用 `python:3.12-slim` + `openjdk-17-jre-headless` | 需同时具备 Python 3.12 与 Java 17；避免跨基础镜像复制 venv |
| 4 | 数据库初始化采用 compose 逐个白名单挂载 SQL，显式排除 `newsql/public.sql` 与 `restore_dropped_tables_20261022.sql` | 后者含 `DROP TABLE`，不能当迁移执行（doc-database §1） |
| 5 | `MINIO_ENDPOINT` 设为宿主机可达地址 `${PUBLIC_HOST}:${MINIO_PORT}` | Java 侧无 public-base-url 配置，预签名 URL 必须浏览器可达；后端经宿主机映射端口访问同一地址 |
| 6 | 所有裸 `${VAR}` 占位符在 `.env.example` 给可启动的占位值；真实 AI 密钥由用户替换 | 缺键启动失败，但空白主机无密钥也应能起容器并打开页面 |
| 7 | 镜像前缀可通过 `REGISTRY_PREFIX` 覆盖，默认官方仓库 | 兼容受限网络；不写死第三方镜像站 |
| 8 | 所有服务 `restart: unless-stopped`；脚本负责生成 `.env`、构建、启动、健康检查与结果打印 | 满足自启动与一键执行要求 |

## 3. 验收项

1. 仅安装 Docker + Compose 的主机执行 `bash deploy/deploy.sh` 后，四个容器全部 `Up`，`backend` 健康检查通过。
2. 浏览器访问 `http://<PUBLIC_HOST>:<FRONTEND_PORT>` 能看到前端页面；`GET /api/homework/task/list` 经 nginx 返回 `code=0`。
3. 数据库自动建表并写入 RBAC 种子；`GET /api/...` 不因缺表报错。
4. MinIO 控制台与 S3 API 端口可达；后端日志无 `MINIO_*` 缺键错误。
5. `docker compose logs -f backend` 能看到 Spring Boot 启动日志；重启 Docker  daemon 后容器自动恢复。
6. 文档同步：`doc.md` 地图、`doc-devops.md` §5/§8 不再写“后端无 Dockerfile / 无部署脚本”。
