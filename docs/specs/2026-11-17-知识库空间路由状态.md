# 知识库空间路由状态（URL 承载当前打开的空间）

日期：2026-11-17 ｜ 模块：`frontend/src/views/knowledgebase`、`frontend/src/router`
上游规范：[docs/doc.md](../doc.md) ｜ 需求来源：2026-11-17 用户要求「点击知识库应带上对应 id，形如 `/index/knowledge-base?space=id`」
相关：[docs/doc-conventions.md](../doc-conventions.md) §5、[docs/doc-knowledgebase.md](../doc-knowledgebase.md) §2.4、[specs/2026-11-16-模板生成页路由状态.md](./2026-11-16-模板生成页路由状态.md)

## 1. 问题陈述

知识库页（`/index/knowledge-base`）当前把「打开哪个空间」「看哪篇文档」「是否在上传页」全部放在组件内存里：

- 点击空间卡片后地址栏不变，无法把「某个知识库」发给别人或收藏；
- 刷新后总是回到空间列表，正在浏览的空间丢失；
- 浏览器前进 / 后退不参与空间切换，地址与画面不一致。

## 2. 方案概述

- **URL 契约**：`/index/knowledge-base?space=<spaceId>`；无 `space` 即空间列表。
- **状态模型**：URL 为「当前打开的空间」的唯一真相源。点击空间、返回列表只负责 `router.push` / `router.replace`；页面用 `watch(() => route.query.space, immediate)` 驱动载入与复位。
- **归属判定**：`spaceId` 先在自己的空间列表（`/space/list`，后端已按 `creator` 过滤）中查找，命中 = 可写；否则在公有库列表（`/space/public-list`，后端只返回他人的公有空间）中查找，命中 = 只读浏览；两处都没有 = 地址失效。
- **只改前端**：不改路由声明、不改后端接口、不改鉴权。

## 3. 口径（已确认）

| # | 决策 | 结论 |
| --- | --- | --- |
| D1 | 参数形状 | 单数 `space`，值为正整数；重复的 `?space=1&space=2` 取第一个 |
| D2 | 路由声明 | `user.routes.js` 不变（query 不需要路径参数）；`name` 仍为 `knowledge-base` |
| D3 | 进入空间 | 点击自己的 / 他人的公有空间卡片统一 `push` `?space=<id>`，只读与否由 URL 解析结果决定 |
| D4 | 返回列表 | 文档列表页的「返回」`push` 基础地址（无 query），不调用 `router.back()` |
| D5 | 自动选中 | 进入空间后仍默认选中第一篇文档；**文档选择、上传页不进 URL** |
| D6 | 地址失效 | 非数字 / 非正整数 / 两处列表都找不到 → toast + `replace` 回基础地址 |
| D7 | 载入失败 | 列表接口失败 → toast，保留深链 URL 并回落空间列表（刷新可重试）；文档接口失败 → toast，保留空间壳与空文档区 |
| D8 | 并发 | 快速切换空间时用请求令牌丢弃过期响应：地址与画面不串 |
| D9 | 侧栏 | 路径未变，`isPathActive` 前缀匹配天然保持高亮；点菜单回基础地址（`router.push(path)` 会清掉 query） |
| D10 | 测试 | URL 解析 / 拼接抽纯函数，`node --test` 覆盖 |
| D11 | 文档 | 本 spec + 回写 `doc-conventions.md` §5.2、`doc-knowledgebase.md` §2.5；不写 ADR |

### 3.1 默认口径

- 空间列表、公有库列表在深链进入时先载入完成，再判定归属，避免「自己的空间被误判为只读」。
- 从空间页返回列表会重新拉取两份空间列表（空间内文档数量可能已变化），与改造前行为一致。
- 非法 `space` 参数由页面校验后回退，不新增路由守卫。
- 上传页（`currentLevel = 'upload'`）是过程态，刷新后回到该空间的文档列表。
- 同一地址重复 `push` 做前置比较，避免 redundant navigation。

## 4. 验收项

| # | 场景 | 预期 |
| --- | --- | --- |
| AC1 | 点击自己的空间卡片 | URL 变为 `/index/knowledge-base?space=<id>`；文档区展示该空间文档 |
| AC2 | 点击公有库卡片 | URL 同样带 `?space=<id>`；文档区只读，无上传 / 删除入口 |
| AC3 | 在 `?space=<id>` 刷新 | 直接进入该空间；自己的可写、他人的公有只读 |
| AC4 | 点文档列表页「返回」 | URL 回到 `/index/knowledge-base`；空间列表重新载入 |
| AC5 | 按浏览器后退 | 从空间回到列表；前进再次进入同一空间 |
| AC6 | 手输 `?space=abc`、`?space=0`、`?space=-1` | toast + `replace` 回基础地址 |
| AC7 | 手输不存在的空间 id（含他人的私有空间） | toast + `replace` 回基础地址 |
| AC8 | 快速切换两个空间 | 最终画面与地址栏一致，不出现串数据 |
| AC9 | 在 `?space=<id>` 下看侧边栏 | 「教学知识库」保持高亮；点该菜单回基础地址 |
| AC10 | 进入上传页后刷新 | 回到 `?space=<id>` 的文档列表 |
| AC11 | 断网刷新 `?space=<id>` | 地址保留；toast 载入失败并显示空间列表，恢复网络后刷新进入该空间 |

## 6. 明确不做

- 不把文档选择、上传页、创建 / 编辑弹窗写入 URL。
- 不新增「按 id 查空间详情」接口；归属判定复用现有两份列表。
- 不改后端归属 / 可见性 / 鉴权逻辑，不写 ADR（决策可逆、局限单页）。
- 不引入 `@vue/test-utils` / jsdom 组件测试栈。
