# 放映页联动数字人口型（presenter 身份）

> ⚠️ **已被取代（同一天）**：本文描述的 `presenter` 身份、`GET /meeting/present`、放映页进房间订阅数字人音频轨这一整套**已全部删除**，口型改由「放映页**本页播报的音频**」驱动、声音随屏幕共享到学生端 —— 见 [docs/16](../16-PPT演讲与模拟会议方案.md) §5.7 与同目录的《讲稿播报改为本页播放》spec。

## 1. 问题陈述

需求原话：**「本标签页联动会议」——否则同步不了数字人口型，也谈不上操控 PPT 翻页。** 期望的链路是「本标签页处于放映状态 → 教师端点『开始演讲』→ 数字人播报（本轮内容 mock 为「你好」）→ 其他端看到口型、听到声音」。

改造后的动线（上一份 spec）已经把**被共享的那一屏**定成 PPT 页的放映标签页，于是暴露出两个各自成立的硬事实：

**① 放映页拿不到声音，所以它不会动嘴。** `views/ppt/index.vue` 的 Live2D 从不调 `setParameterValueById`（全仓唯一会写 `ParamMouthOpenY` 的是 `views/meeting/components/DigitalHumanAvatar.vue:38-42`，它只挂在学生会议室）。而学生听到的声音只可能来自房间里的数字人音频轨——屏幕共享轨是 `audio: false`。于是**学生画面里的数字人是一张不动的脸**：嘴不动，声音却在响。

**② 联动不能靠「控制台把响度广播过来」。** 那样要求控制台标签页始终不被浏览器节流（老师一切回放映页看学生视角，控制台进后台，RAF 就被降频甚至暂停），口型会在最需要的时候卡住。

## 2. 方案概述

一句话：**让放映页自己进房间，用学生的同一条音频轨驱动口型。**

- 后端新增只读身份 `presenter` 与 `GET /meeting/present`（用 `hostToken` 换令牌）；
- 前端新增 `hooks/usePresenterRoom.js`（presenter 身份进房、**静音**订阅数字人音频轨、只暴露口型响度）；
- PPT 页在「放映态 + 地址里有 `?meetid=`」时连上，把 `mouthLevel` 写进本页 Live2D；
- `utils/attendees.js` 把 `presenter` 与 `digital-human` 排除出名单与在线人数（两者都常驻房间，不排除就是人数虚高）；
- 控制台新增「开始演讲」**信号**按钮（本轮内容 mock 为「你好」），手输播报框保留作调试入口。

## 3. 用户故事（可验收）

1. 在 PPT 页建会进入放映后，地址为 `/index/ppt?screen=1&meetid={会议号}`；刷新这条地址仍能恢复放映并重新连上房间。
2. 控制台顶栏出现「开始演讲」；点击后数字人在房间里播报「你好」：**学生端**听到声音且数字人张嘴；**放映页**右上角数字人同步张嘴。
3. 控制台的在线人数**不含**放映页与数字人（与改造前相比不多 1）；`AttendeeList` 里也没有它们。
4. 放映页与控制台**同时在线不互相顶号**（LiveKit identity 不同）。
5. 退出放映（ESC）后放映页断开房间；再次进入放映会重新连上。
6. 不带 `meetid` 的 `/index/ppt?screen=1` 不连房间、不动嘴，也不影响任何学生。
7. LiveKit 未配置/未启动时：`GET /meeting/present` 返回可读错误（`1_007_000_010`）；放映页**不报错、不中断放映**，只是数字人不动嘴。
8. 放映页的音频元素是**静音**的（同一台机器上不会出现两份声音），但响度仍能驱动口型。
9. 「数字人播报」手输框仍在，且能播任意文本（多源调试入口）。
10. 后端 `MeetingServiceImplTest` / `LiveKitTokenServiceTest` 锁住：`present` 必须走 `createPresenterToken`（不得复用 `host`）、未配置时不返回空壳。

## 4. 已定决策（不再翻案）

| # | 议题 | 决策 | 理由 |
| --- | --- | --- | --- |
| 1 | 联动通道 | **放映页进房间**（房间即总线） | 只有订阅同一条音频轨，嘴与声音才可能同步；也省掉第三种通道 |
| 2 | 令牌身份 | **独立身份 `presenter`**，权限 `canPublish=false` / `canSubscribe=true` / `canPublishData=true` | 复用 `host` 会与服务端 identity 去重打架（同机两个标签页互相顶号）；复用 `attendee-{id}` 会往台账写参会记录 |
| 3 | 令牌下发 | **新增 `GET /meeting/present`**，不扩 `detail` 的响应 | 语义单一：`detail` = 主持人（可发布），`present` = 放映页（只订阅） |
| 4 | 响度来源 | **本页订阅音频轨**，不是控制台转发 | 控制台一旦进后台，浏览器会节流它的定时器 |
| 5 | 音频输出 | 放映页**静音**（元素仍 attach） | 同机控制台已经在放声音；且实测「只拿 `mediaStream` 接 AnalyserNode」分析器一直是静音帧 |
| 6 | 翻页遥控 | **本轮不做**（只是先不做，不是不做） | 要先把「页码回传」用起来；本轮目标是口型链路先通 |
| 7 | 「开始演讲」语义 | **开始信号**，本轮内容 mock 为「你好」 | 下一轮把取文本那步换成当前页 `remark` / AI 现场讲词时，信号本身不变 |
| 8 | 取消 | **本轮不做**（后端 `say/cancel` 未落地） | mock 只有一句；换成整页讲稿之前必须先补 |
| 9 | 手输播报框 | **保留** | 它是现在唯一能验证 worker / 房间 / 音频轨是否通的旁路 |

## 5. 测试决策

**后端**（本模块有测试基建，必须写）：`LiveKitTokenServiceTest` 新增 `presenterToken`（字段级断言：identity、`canPublish=false`、`canPublishData=true`、`role=4`）；`MeetingServiceImplTest` 新增三条——用 `presenter` 那一路签发且**从不调用** `createHostToken`、未配置时抛 `1_007_000_010`、已结束/凭据不符都拒绝。

**前端**：`attendees.js` 名单纯函数的既有接缝上补一条——数字人与放映页不出现在名单、不计入人数（`tests/attendees.test.js`）。放映页的房间接线与口型属「跨标签页 + SFC 内」的动线，仓库现有三种手法都够不到，与上一份 spec 同口径：**不新增测试框架**，交给真机验收。

**完成定义（实际达成）**：后端 `tb-module-lecture` **51/51**；前端 `npm test` **175/175**；`eslint` + `oxlint` 干净；`vite build` 通过。
**手工验收**：docs/16 §11.2 第 19~21 条，必须**两台设备 + 真实 worker**（口型与声音是否同步，单测与单机都证明不了）。

## 6. 明确不做（含接受的代价）

- **翻页遥控**（控制台 → 放映页翻页）：留到下一轮，届时用令牌里已经留好的 `canPublishData` 走 DataChannel。
- **取消播报**：所以本轮「开始演讲」发出后只能等它念完——换成整页讲稿前必须补上 `say/cancel`（docs/18 §5.4）。
- **学生端原生渲染 PPT / 页码同步**：维持 docs/18 §11 的口径。
- **形象与口型合并成一份**：放映页只是补齐了「会动嘴」，两份实现仍然并存（docs/18 C 段）。
- **`speak` 试听通路、`narrate`、串行播报队列**：仍属 docs/18 的 A/B 段，本轮不动。
- 复用被回退的 `c50d344`（演讲台 + `usePresenter` + `speech-queue` + `say/cancel` + `/ppt/speech/speak`）中的任何代码：本轮明确不复用。
