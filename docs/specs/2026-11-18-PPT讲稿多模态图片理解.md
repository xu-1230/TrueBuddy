# PPT 讲稿多模态图片理解实施规格

日期：2026-11-18 ｜ 模块：`frontend/src/views/ppt`、`backend/tb-module-lecture`
上游规范：[docs/doc.md](../doc.md)、[docs/doc-conventions.md](../doc-conventions.md)
相关：[docs/doc-lecture.md](../doc-lecture.md)、[docs/doc-api.md](../doc-api.md)

## 1. 问题陈述

`/index/ppt` 的 AI 讲稿只读页面文字与备注：`utils/slide-text.js` 明确把 `image` 排除在文本提取之外；`utils/lesson-runner.js` 在 `remark` 与 `text` 都为空时直接跳过该页。结果是纯图片页、图表截图页在「AI 优化」与「AI 现场讲词」两条链路里都得不到有效讲稿。当前配置的 `deepseek-flash` 已支持 `image_url` 多图输入（实测 3 张 base64 图片可被正确消费），缺的是前端提取、请求字段与后端多模态消息组装。

## 2. 范围

- **覆盖**：AI 优化本页、AI 优化全部、AI 现场讲词（narrate）。
- **不做**：背景图、形状图片填充、视频帧、远程 URL 图片；不做服务端 EMF/WMF 转换；不新增图片状态 UI 或全局开关。
- **不改**：verbatim 照读仍只读备注；PPT 数据仍由前端本地持有，接口保持无状态。

## 3. 口径

| # | 决策 | 结论 |
| --- | --- | --- |
| D1 | 图片来源 | 只取 `slide.elements` 中 `type = image` 且 `src` 为 `data:image/*` 的元素 |
| D2 | 数量与筛选 | 每页最多 3 张；按元素面积降序；面积小于页面面积 1% 的过滤；按 `src` 去重 |
| D3 | 压缩 | 前端 Canvas：最长边 1280px、JPEG 0.82、单张 data URL ≤ 420KB；透明图铺白底；有 `clip.range` 时按可见区域裁剪 |
| D4 | 无法解码 | EMF/WMF 等浏览器不可解码格式静默跳过，不提示 |
| D5 | 请求字段 | `pages[].images: string[]`（data URL）；narrate 顶层 `images` |
| D6 | 分片 | 「优化全部」前端每片最多 6 页；每片携带全篇 `totalPages` 与 `outline` |
| D7 | 模型分批 | 纯文字批次仍 `batch-size`（默认 8）；含图片的批次最多 2 页 |
| D8 | 多模态消息 | 有图片时用 `UserMessage.builder().text(prompt).media(media)`；无图片时保持 `.user(String)` |
| D9 | 提示词 | 图片是页面内容的一部分；与文字冲突时由模型比较后自行判断；不得编造不可见信息；prompt 注明每张图属于哪页 |
| D10 | 失败语义 | 沿用两轮补跑 + `failedIndexes` + 前端「只重试失败页」；分片 HTTP 失败只标记该片页面失败 |
| D11 | 进度 | 复用「AI 优化全部备注」按钮 loading 文案：`生成中 n/N 页` |
| D12 | 纯图片页 | `lesson-runner` 的空页判断改为 `remark / text / images` 任一非空即可生成 |

## 4. 接口变化

`POST /api/ppt/speech/optimize`：

```jsonc
{
  "targetSeconds": 480,
  "totalPages": 30,                  // 新增，可空；缺省 pages.size()
  "outline": ["封面", "项目背景"],    // 新增，可空；缺省按本批 pages 生成
  "pages": [
    {
      "index": 3,
      "title": "系统架构",
      "text": "……",
      "remark": "……",
      "images": ["data:image/jpeg;base64,..."] // 新增，最多 3 张
    }
  ]
}
```

`POST /api/ppt/speech/narrate`：新增顶层 `images: string[]`。

后端对图片做格式与体积校验：只接受 `image/jpeg`、`image/png`、`image/webp`；单张解码后 ≤ 512KB；每页最多 3 张。非法图片静默丢弃并记 debug 日志。

## 5. 前端落点

| 文件 | 作用 |
| --- | --- |
| `views/ppt/utils/slide-images.js` | 选图（面积/去重/上限）、裁剪、Canvas 压缩、缓存与清理 |
| `views/ppt/utils/speech-chunks.js` | 6 页分片、全篇 outline、分片结果合并 |
| `views/ppt/index.vue` | 带图页面信息构造、分片跑批与进度、单页/重试带全篇上下文、narrate 异步页面信息 |
| `views/ppt/utils/lesson-runner.js` | `await getPageInfo(page)`；空页判断加入 `images` |

## 6. 后端落点

| 文件 | 作用 |
| --- | --- |
| `PptSpeechPageVO` / `PptSpeechNarrateReqVO` | 新增 `images` |
| `PptSpeechOptimizeReqVO` | 新增 `totalPages` / `outline` |
| `PptSpeechServiceImpl` | data URL → `Media`、视觉批次切分、全篇大纲覆盖、narrate 空输入判断 |
| `SpeechScriptUtils` | 图片归属说明、narrate 图片提示、兼容旧调用的大纲回退 |
| `PptPromptConstants` | 两条 system prompt 增加图片理解规则 |

## 7. 验收项

1. 导入含图片的 `.pptx`，单页「AI 优化本页」生成的讲稿能提到图片中的可见内容。
2. 「AI 优化全部」按 6 页分片，按钮显示 `生成中 n/N 页`；最终弹窗仍按页展示，失败页可单独重试。
3. 纯图片页在放映态 AI 自主模式下不再被 `page-skipped`，能够生成现场讲词。
4. 无图片的页面请求体与旧版一致（不出现 `images` 字段），后端纯文字路径行为不变。
5. 超过 3 张、面积过小、EMF/WMF、非法 base64 的图片均被跳过，不影响其他页生成。
6. 全篇 `targetSeconds` 在分片后仍按全篇页数均摊，不因分片放大。
7. `npm run lint`、`npm test`、`npm run build`、`./mvnw -pl tb-module-lecture -am test` 全部通过。
