# 模拟会议生命周期修复

日期：2026-10-09 ｜ 模块：`backend/tb-module-lecture`（`meeting` 包）+ `frontend/src/views/meeting`
决策记录：[ADR-0001](../adr/0001-入会人数上限闸门作废.md)、[ADR-0002](../adr/0002-在线状态唯一真相源为房间事件.md)、[ADR-0003](../adr/0003-主持人凭据不提供重新签发路径.md) ｜ 术语：[CONTEXT.md](../../CONTEXT.md)

## 1. 问题陈述

`join()` 用 `countOnline(meetingId) >= max-attendees` 决定能否入会，而 `online` 是一个**没有任何写入方能把它改回 false 的字段**：既没有 `/meeting/leave` 接口，前端也没有 `pagehide`/`beforeunload`（`MeetingRoomView.vue:253` 只在组件卸载路径调 `room.disconnect()`）。学生每关一次标签页就留下一行永久的 `online=true`，累计 20 行后会议在"实际只有一人在线"时抛「人数已满」，无人能救——只能重开。这是会当场翻车的演示阻断项。

同一字段还有第二个消费者，且它比后端更糟：

| 位置 | 行为 |
| --- | --- |
| `stores/meeting.js:24` | `onlineCount` 是前端自己按 `attendees[].online` 算的，**后端 `MeetingInfoVO.onlineCount` 没有任何消费方**（纯死字段） |
| `stores/meeting.js:56` | LiveKit 房间事件把 `attendees` 整体覆盖为房间成员，`useLiveKitRoom.js:55` 硬编码 `online: true` |
| `MeetingRoomView.vue:193` | 10s 轮询 `state` 又用 DB 名单整体覆盖同一个 ref |

即：**房间事件与 DB 名单共用同一个 `attendees` ref**，两个真相源轮流写它。

> **实现期更正**：我写 spec 时说的"每 10 秒被覆盖一次"过重了——`MeetingRoomView.vue` 的轮询其实有闸门（`if (seed || store.connection !== 'connected')`），覆盖只发生在房间未连接的时间窗。真正的问题是**结构性的**：同一个数组被两种形状的写入方写（房间项 `{id: identity, online: true}` 硬编码 vs DB 项 `{id: number, online: 脏值}`），而 `stores/meeting.js:24` 用 `item.online` 求和——于是降级窗口里 DB 的脏 `online` 就直接变成页面上的"在线人数"，`AttendeeList.vue:14` 的"已离开"标签把这份漂移渲染了出来。结论不变（两者必须分家），成因比我最初写的更准确。

顺带确认的两个认知纠正（避免按错误前提施工）：`LectureMeetingMessageMapper.selectById` 缺 `deleted = FALSE` **不是 bug**（`MeetingServiceImpl:270` 取的是同事务刚插入的行）；`attendee.role` **不是死列**（`:376` 在用它给名单标角色）。

## 2. 方案概述

一句话：**把"在线"这个词的唯一所有权交给 LiveKit 房间事件，DB 退成一本只写的台账。**

- 入会闸门删除——不再有需要可信的在线计数。
- `lecture_meeting_attendee` 删 `online` 列，`leaveTime IS NULL` 即"尚未显式离开"；新增 `POST /meeting/leave` 写 `leaveTime`。
- 前端名单拆成两份状态：房间成员（渲染为在线名单与在线数）与入会台账（仅在房间不可用时降级显示）。
- `hostToken` 不做找回，只做显式提醒。

## 3. 用户故事

**A. 入会不再被脏数据卡死**
1. 学生关闭标签页 25 次后，第 26 个学生仍能用同一会议号成功入会，不出现「人数已满」。
2. `application.yml` 中不存在 `max-attendees` 键；`MeetingProperties` 无 `maxAttendees` 字段；`ErrorCodeConstants` 无 `1_007_000_005`。
3. `LectureMeetingAttendeeMapper` 无 `countOnline` 方法（零调用方即删，不留僵尸）。

**B. 在线名单诚实**
4. 老师控制台的在线人数与名单在成员进出时**立即**随房间事件更新，且**不会**被 10s 轮询的 REST 响应覆盖。
5. 房间可用时，`AttendeeList` 列表项全部来自房间成员；组件不再渲染"已离开"分支。
6. ~~LiveKit 断开（`connection !== 'connected'`）时，`AttendeeList` 降级显示入会台账，并在文案中明示这是"入会记录"而非当前在线。~~
   **UI 轮次推翻（2026-10-09）**：降级时**不列名单、也不报人数**，只说明「实时连接不可用，暂时拿不到在线成员」。理由是台账里「尚未显式离开」的行恰恰包含早已关页面走掉的人，把它列成名单正好在最不该说谎的时候说谎。连带后果：前端不再消费 REST 的 `attendees`，`joinLedger` 已从 store 移除（后端仍返回该字段作为台账接口）。
7. `GET /meeting/detail` 与 `GET /meeting/state` 的 `meeting` 对象不再包含 `onlineCount` 键；`attendeeCount` 保留且等于该会累计入会行数。
8. `MeetingAttendeeVO` 无 `online` 字段，新增 `leaveTime`（可为 null）。

**C. 显式离开被记账**
9. 学生在 SPA 内离开会议室路由时（`onBeforeUnmount`），`POST /meeting/leave`（`meetingNo` + `attendeeToken`）被发出且该行 `leaveTime` 被写入。**收窄说明**：原故事写的是"关闭标签页/`pagehide`"，实现期否掉了——刷新也走 `pagehide`，而刷新后 sessionStorage 里的凭据会继续复用、不会重新 `join`，那时写 `leave` 等于留下一条"已离开但其实还在"的假事实，比留着不动更糟。
10. 同一 `attendeeToken` 重复调 leave **返回成功且不报错**（幂等），第二次不改写已有的 `leaveTime`。
11. leave 传错误 `attendeeToken` 返回 `1_007_000_009`；传已结束会议返回 `1_007_000_002`。
12. 老师结束会议时，所有 `leaveTime IS NULL` 的行被补写 `leaveTime`（`markAllOffline` → `markAllLeft`，`WHERE leave_time IS NULL` 而非 `WHERE online = TRUE`）。
13. 学生崩溃/断网/**刷新页面**时台账留下一行 `leaveTime IS NULL`，此为预期行为，且不参与任何"在线"判断。

**D. 主持人凭据**
14. 建会成功响应里，`hostToken` 单独成行展示并带「复制」按钮，旁注「凭据仅此一次显示，丢失无法找回」。
15. `localStorage` 中该会议号的会话读不到 `hostToken` 时，控制台显示「主持人凭据已丢失，请重新建会」，不再抛未捕获异常或静默空白。
16. 代码中不存在任何按 `meetingNo` 重新签发 `hostToken` 的接口或 SQL。

**E. 清理**
17. `lecture_meeting` 表与 `LectureMeetingDO` 均无 `planned_minutes`/`document_id`；建表脚本注释不再声称"预留给演讲稿阶段"。
18. `LectureMeetingMapper` 无 `selectById`；`LectureMeetingMessageMapper.selectById` 的 SQL 含 `deleted = FALSE`。

## 5. 测试决策

**接缝一（后端主接缝）＝ `MeetingService` 接口。** 新建 `MeetingServiceImplTest`，Mockito mock 三个 mapper + `LiveKitTokenService` + `MeetingProperties`，不启 Spring 上下文、不连库。覆盖：故事 1（超限仍可 join）、7（响应无 onlineCount）、9/10/11（leave 幂等与错误分支）、12（close 调 `markAllLeft` 而非旧方法）。
理由：本环境无可用的独立测试库，而 docs/11 §2.2 禁止污染 `tb` 生产库——所以**本期不做 `@SpringBootTest`/MockMvc，也不做 mapper SQL 集成测试**。代价明确写出：`markAllLeft` 的 `WHERE leave_time IS NULL`、`deleted = FALSE` 补齐、删列后的 DDL 这三项**只由手工验收覆盖**（docs/11 §4 第 4 条），实现在 SQL 文本上必须逐字 review。

**接缝二（前端主接缝）＝ 名单拆分后的纯函数。** 新增 `frontend/src/views/meeting/utils/attendees.js`，导出 `fromRoomParticipants(list)` 与 `pickDisplayAttendees({ roomAttendees, joinLedger, connection })`，把故事 4/5/6 的"谁覆盖谁"裁决逻辑收进一个无 Vue、无 LiveKit 依赖的模块。用现有 `node --test` 范式落在 `frontend/tests/attendees.test.js`（与 `run-state.iterations.test.js` 同风格）。
理由：docs/11 §3.1 明确前端**没有** vitest/jest/playwright 配置；不为本次修复引入测试框架。

**完成定义（实际达成情况）：** `./mvnw -o -pl tb-module-lecture -am test` 全绿 —— **35/35**（原 28 + `MeetingServiceImplTest` 7）；`node --test tests/attendees.test.js` 5/5；oxlint + eslint 对改动文件干净；`vite build` 通过。
**更正**：原写「`npm test` 全绿」不成立 —— `tests/variable-sources.test.js` 有 1 条**既有** workflow 用例在 HEAD 上就是红的（断言 `EndNode.vue` 的未绑定告警），与本次修复无关，不在本票范围内修。18 条故事中不依赖真实 LiveKit 的已验证；故事 4/5/6/11 标记为「待真实浏览器联调」，验收步骤已写进 docs/16 §11.2 第 10~14 条。
