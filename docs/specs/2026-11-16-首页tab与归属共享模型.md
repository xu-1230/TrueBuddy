# 首页 Tab 改版与知识库/工作流归属共享模型

## 1. 问题陈述

系统首页（`/index/home`）Zone C 的五个 tab（综合/知识库/工作流/文档生成/会话）只是资产卡过滤器：批改与会议这两类核心产物在首页没有任何入口，会话卡片与工作流卡片信息重复；知识库与工作流是**全局池**（列表不按人过滤、所有人可见可改），没有归属与共享概念，「把别人的知识库/工作流添加为自己的」无从谈起；批改结果 SSE 直出后即消失，没有任何可回看的结果页。

## 2. 方案概述

- **Tab 双行为模型**：六个 tab = 三个过滤型（综合/知识库/工作流，过滤 Zone D 资产卡）+ 三个跳转型（文档/批改/会议，点击直接路由跳转，不占用过滤态）。
- **信息流收敛**：会话来源彻底移除，来源剩知识库空间、工作流、文档生成历史三类；后端列表按 `creator` 过滤，「我的资产」名副其实。
- **归属与共享**：`kb_space` / `workflow` 增加 `visibility`（0=私有/1=公有，存量刷私有、新建默认私有），编辑/删除仅创建者，公有对他人只读；「添加为自己的」= **fork 深拷贝独立副本**（详见 [ADR 0006](../adr/0006-知识库与工作流归属与共享模型.md)）。
- **批改结果落库**：新增评分记录表，前端执行终态后回写；批改页加历史抽屉回看配置与逐学生评分。

## 4. 已定决策（不再翻案）

| # | 议题 | 决策 | 理由 |
| --- | --- | --- | --- |
| 1 | Tab 行为模型 | 双行为：综合/知识库/工作流过滤资产卡；文档/批改/会议点击直接跳页，不占用过滤态 | 跳转型 tab 承担模块入口，过滤型 tab 保留「我的资产」价值 |
| 2 | 文档 tab 落点 | `/index/doc-template` 现状页，**零改动** | 「历史记录→生成列表→点文件」层级已存在于该页历史抽屉 |
| 3 | 会议 tab 落点 | `/index/meeting` 现状 console，**零改动** | 本机凭据「回到会议」机制已存在（localStorage） |
| 4 | 批改 tab 落点 | 现有执行页 + 页内历史抽屉（仿文档模板页），不新建独立路由页 | 与文档模板页同构，改动最小且满足「结果页面」 |
| 5 | 会话 | tab 删除、信息流来源彻底移除；工作流会话功能本身不动 | 用户拍板 |
| 6 | 归属真相源 | 复用审计列 `creator`，不新建 owner 表 | 框架已自动填充，存量数据可回填 |
| 7 | 默认可见性 | **全部私有**：存量刷私有 + 新建默认私有 | 用户拍板（比推荐更严）；权限模型从第一天就是真的 |
| 8 | 编辑权 | 编辑/删除仅创建者；公有对他人只读 | fork 模型的自然推论 |
| 9 | 「添加为自己的」语义 | **统一 fork 深拷贝独立副本**（否决引用订阅、混合模式） | 用户拍板；副本完全拥有、可自由改造，无同步复杂度 |
| 10 | 公有的能力边界 | 公有 = 可见 + 可 fork；**不可直接被检索**，不可免 fork 直跑 | 用户拍板「严格只能选我的」；fork 是使用他人资源的唯一通道 |
| 11 | builtin 豁免 | 内置「标准批改作业」视为系统资产：全员可见可运行免 fork（推导规则） | 否则批改链路的默认工作流会因 creator 过滤消失 |
| 12 | 批改结果持久化 | **结构化落库**（逐学生记录表），否决「导出文件留存」与「只回看配置」 | 用户拍板；「结果页面」必须能回看完整评分 |
| 13 | 结果回写的写入方 | **前端**：执行终态（`conversation.chat.completed` 帧 + records 齐备）后调新接口回写 | 批改执行由前端驱动（doc-homework §4），后端不感知执行进程，回写只能挂在前端 |
| 14 | 公有库发现面 | 模块页内浏览区：知识库页、画布页各加「公有库」入口（列表 + fork 按钮） | **综合推导项**（拷问未覆盖）：公有必须可见才有可 fork；落位在票据评审时可调整 |
| 15 | 列表过滤位置 | creator 过滤做在**后端**（`getSpaceList` / `listWorkflows`），前端不自行过滤 | 数据安全边界必须在服务端 |

## 6. 明确不做（含接受的代价）

- **引用订阅 / 混合共享模式**：已被 fork 决策否决（代价：知识库 fork 需复制向量行，大库 fork 有分钟级成本，接受——低频操作）。
- **免 fork 直跑他人公有工作流**、**公有库直接检索**：公有只开放「可见 + 可 fork」。
- **fork 副本与原库的同步/升级**：副本生成即完全独立。
- **会议、文档生成模块的功能改动**：两个 tab 是纯跳转，零后端。
- **批改结果导出接口**（xlsx/csv）：doc-homework 既有规划项，本次只落库与回看，导出另开。
- **管理端全局视图**：管理员是否绕过 creator 过滤，本次不动（现状管理端无此需求）。
- **首页 Zone A/B（运营位、可用工具卡）改动**：只动 Zone C/D 与信息流。
- **工作流会话功能**：会话按 creator 隔离现状已存在（`ChatController` 要求登录并按用户隔离），不变。

## 7. 补充说明（实现口径）

- **fork 技术口径（知识库）**：复制 `kb_space` → `kb_document`（仅 `status=2 已向量化` 的文档，未完成的不带入）→ `kb_document_parse_block` → `kb_document_chunk` → `vector_store`（`INSERT … SELECT` 改写 metadata 的 `spaceId/documentId/chunkId` 并生成新 uuid）；副本空间命名「原名（副本）」。
- **fork 技术口径（工作流）**：新雪花 id、拷 `name（加「（副本）」）`/`description`/`schema_json`，`status=0 草稿`。
- **新表命名**：`homework_grading_result`（刻意避开废弃旧表名 `homework_grading_task` / `homework_grading_record`，防止与恢复脚本混淆）；记录字段与内置定义输出节点六参对齐（student/score/grade/comment/deductions/readFiles），另存 `task_id`、`conversation_id`、回写时间；`deductions`/`readFiles` 用 JSONB。
- **任务状态机**：`0 已上传待批改 →（前端开始执行）1 批改中 →（前端终态回写）2 成功 / 3 部分成功 / 4 失败`；`visibility` 列同步加在 `kb_space` / `workflow` 两表。
- **跳转型 tab 实现**：`HOME_TABS` 配置拆为 filter/jump 两类字段，jump 项点击 `router.push` 且不改 `activeTab`，避免「点完跳转回来过滤态被换页」。
- **迁移方式**：存量刷私有走一次性 SQL 或启动迁移，落点在票据拆分时定。
- **接受的现状风险**：存量刷私有后，多账号演示时彼此看不到对方旧资源（US7/US13 的直接后果，已在决策 7 拍板接受）。
