# 2026-11-17 文档 AI 聊天真实接入（选区 + SSE 编辑 + 版本撤回）

## 1. 范围

把文档模板查看页右侧的 AI 聊天从纯前端 mock 改为真实链路：

1. 左侧 docx 预览支持多选元素，选中项以 ghost-chip 形式进入 composer；
2. 用户输入修改要求后，后端调用 LLM 产出结构化编辑指令，经 docx-mcp 落盘、校验、上传生成新版本；
3. 查看区自动切到新版本，chat-meta 提供撤回（级联丢弃后续修改）；
4. 生成记录按登录用户隔离：只有创建者可以看到、编辑、撤回自己的文档；
5. 聊天历史本次**不持久化**，前端会话态；刷新后聊天与撤回入口消失，但文档版本与当前版本保留。

## 2. 已确认口径

- 结果列表 / 首页「文档」tab 不展示工作区、版本号或版本下拉；只保留现有结果卡。
- 不新增 workspace 表：`doc_template_file` 根行即工作区；根文件即 v1。
- 新增 `doc_template_version` 只存 v2+；`doc_template_file.current_version_id` 为空表示 v1。
- 存量生成记录 creator 统一刷为 `2902017108@qq.com`（`system_user.id=1`）；新生成保存当前登录用户。
- `/doc-template/**` 移出免登录白名单；生成 / 历史 / 详情 / 聊天 / 撤回都要求登录并按 creator 过滤。
- 选区只是 LLM 上下文提示，不限制修改范围；没有选区时按全文处理。
- 编辑能力：文字替换、单元格写入、插入/删除段落；不改格式、图片、表格行/列。
- LLM 指令校验失败自动修正一次；仍失败则不落版本。
- 自动应用 + 新版本 + 摘要；不二次确认。
- 撤回图标在 chat-meta；允许撤回任意更早编辑并级联；确认后目标版本及后代置 `superseded`，消息灰显失效。
- 聊天不持久化；本轮不建聊天表。

## 3. 数据变更

- `doc_template_file` 增加 `current_version_id BIGINT NULL`。
- 新增 `doc_template_version`（详见 `backend/sql/doc_template_version.sql`）。
- 迁移脚本：`backend/sql/doc_template_chat_edit_20261117.sql`。
- 存量 `doc_template_generation.creator` / `doc_template_file.creator` 为 NULL 的统一刷 1。

## 4. 接口

- `POST /doc-template/chat`（SSE，登录）：`{rootFileId, instruction, selections[], history[]}`。
  事件：`status` / `assistant` / `version` / `error` / `done`。
- `POST /doc-template/chat/undo`（登录）：`{rootFileId, targetVersionId}`。
- `GET /doc-template/detail`：只允许 generation.creator 访问；结果卡的 `src` 指向 `current_version_id` 对应文件。
- `GET /doc-template/history`：只返回当前用户的生成记录。

## 5. 验收

- 元素 locator（p:N / t:N / t:N/r:R/c:C）与 docx-mcp `get_text` / `get_tables` 一致。
- 真实一次编辑生成 vN、预览自动刷新、chat-meta 出现撤回图标、无版本号展示。
- 撤回级联丢弃后续版本；消息灰显失效；当前版本回到 base。
- 无选区按全文编辑；有选区时选区作为高亮上下文。
- 未登录 401；非 creator 看不到记录 / 403 / 404。
- 存量文档 creator=1；新生成 creator=当前登录用户。
- 前端 lint/test/build、后端 compile、真实端到端编辑通过。

## 6. 不做

聊天历史持久化、版本下拉/版本号、redo、表格行/列增删、格式与图片修改、RAG、多用户共享。

## 7. 风险

`docx-preview` 生成的 DOM 必须与 docx-mcp 的正文段落/表格/单元格编号严格一致；先做 locator 对照验证，不通过则回到方案评审再决定是否改用 docx-mcp 渲染 HTML。
