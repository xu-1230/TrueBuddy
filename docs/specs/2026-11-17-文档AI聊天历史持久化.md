# 2026-11-17 文档 AI 聊天历史持久化与加载

## 1. 范围

把文档模板查看页的 AI 聊天记录从「纯前端会话态」改为按文档持久化：

1. 打开 / 切换文档（`doc_template_file` 根行，即工作区）时，加载该文档的历史聊天记录并回显；
2. 一轮对话包含用户指令、助手回复、系统撤回提示，全部落库；
3. 撤回后的目标消息及其后消息标记「已失效」，刷新后保持；
4. 仍按 creator 隔离：只有根文件所有者可以读取与继续对话。

本轮不做：分页 / 清空 / 搜索、聊天记录跨用户共享、附件消息、消息编辑。

## 2. 已确认口径

- 聊天记录归属于根文件（`root_file_id`），与版本链分离；切换版本不重新加载聊天。
- 助手消息通过 `version_id` 关联版本；撤销某次编辑时，消息失效状态与版本 `superseded` 同步。
- 系统提示（撤回说明）也落库，保证刷新后对话完整。
- LLM 上下文仍由前端在请求里携带最近的有效消息；加载历史后自然覆盖跨会话上下文。
- 失败回复（`error`）落库，刷新后仍可见。
- 历史接口要求登录并按根文件 creator 校验，非本人按工作区不存在处理。
- 默认返回最近 200 条、上限 500 条，按时间正序；分页留待后续。

## 3. 数据变更

新增 `doc_template_chat_message`（已建表脚本 `backend/sql/doc_template_chat_message.sql`，迁移脚本 `backend/sql/doc_template_chat_history_20261117.sql`）：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `BIGINT IDENTITY` | 主键 |
| `root_file_id` | `BIGINT NOT NULL` | 工作区（`doc_template_file.id`） |
| `role` | `VARCHAR(16) NOT NULL` | `user` / `assistant` / `system` |
| `content` | `TEXT NOT NULL` | 扁平文本（LLM 上下文 / 兜底展示） |
| `blocks` | `JSONB` | 助手结构化回复块 |
| `selections` | `JSONB` | 用户消息的选区上下文 |
| `version_id` | `BIGINT` | 本次编辑产生的版本；无编辑为 NULL |
| `superseded` | `BOOLEAN NOT NULL DEFAULT FALSE` | 撤回后失效 |
| `error` | `BOOLEAN NOT NULL DEFAULT FALSE` | 失败回复 |
| `creator` | `BIGINT` | 发送人 |
| `create_time` | `TIMESTAMP NOT NULL DEFAULT now()` | 创建时间 |

索引：`(root_file_id, id)`、`(version_id) WHERE version_id IS NOT NULL`。

## 4. 接口

- `GET /doc-template/chat/history?rootFileId=&limit=`（登录）
  - 返回 `CommonResult<List<ChatMessageRespVO>>`，正序；`limit` 默认 200、上限 500。
  - 字段：`id`、`role`、`content`、`blocks`、`selections`、`versionId`、`superseded`、`error`、`createTime`。
- `POST /doc-template/chat`：行为不变；执行过程中写入用户消息与助手消息。
- `POST /doc-template/chat/undo`：响应新增 `notice`（system 消息），用于前端与刷新后的记录保持一致。

## 5. 验收

- 打开文档加载历史；刷新、重新打开、切换文档均正确；切换版本不重载。
- 一次成功编辑后刷新，助手消息仍带版本关联与撤回入口；撤回后目标及之后消息「已失效」，刷新后保持。
- 无编辑 / 报错的一轮对话同样回显。
- 未登录 401；非 creator 按不存在（404 语义）处理；不同文档记录互不串档。
- 后端编译、前端 lint/test/build 通过；数据库迁移可重复执行。

## 6. 不做

聊天分页 / 清空 / 搜索、跨用户共享、附件消息、消息编辑、redo。

## 7. 风险

- 聊天写入与版本写入不在同一事务（聊天为最佳努力持久化）；写库失败只记录日志，不阻断 SSE。
- 历史接口上限 500 条；超长会话需后续补充分页。
- 前端加载与流式回复并发时用请求令牌与 `historyLoading` 防串档。
