# 讲稿播报改为「本页播放 + 共享带声音」

日期：2026-10-10 ｜ 模块：`backend/tb-module-lecture`（`digital` / `ppt` / `meeting` / `livekit`）+ `frontend/src/views/ppt`、`frontend/src/views/meeting`
上游方案：[docs/doc-lecture.md](../doc-lecture.md) §5.7 ｜ 取代：[specs/2026-10-10-放映页联动数字人口型.md](./2026-10-10-放映页联动数字人口型.md)（同日，已标废弃）｜ 相关：[docs/17](../doc-lecture.md)（已废弃）、[docs/18](../doc-lecture.md)

## 1. 一句话

**声音的终点就是被共享的那一页**：后端把讲稿合成为 PCM 并以 SSE 流回放映页，本页播放它、用**同一份音频**驱动口型；那一页正被屏幕共享，声音因此随共享轨到学生端 —— 声画同源，中转那一圈（Node worker → 房间音频轨）被整体删除。

## 2. 变更清单

- 后端新增 `POST /ppt/speech/speak`（`SseEmitter`）：事件 `status`（started/done）、`chunk`（base64 的 48kHz 单声道 16bit PCM）、`error`；**调用方断开即取消合成**（写失败 → 合成侧 `streamingCancel()`）；
- 后端删除：`digital/worker/`（`DigitalHumanWorkerClient` + HTTP 实现）、`LiveKitTokenService` 的 `AGENT_IDENTITY` / `createAgentToken` / `PRESENTER_IDENTITY` / `createPresenterToken`、`POST /meeting/digital/say`、`GET /meeting/present`、`MeetingService.present`、错误码 `1_007_000_015/018/019`、`digital-human-worker/` 整个目录、yml 的 `worker-base-url` / `agent-shared-secret` / `worker-probe-timeout-ms`（`max-concurrent-say` → `max-concurrent-speak`）；
- 后端简化：`GET /meeting/digital/status` 去掉参数与 worker 探测，`available = 开关 && DashScope Key 已配`；
- 前端新增 `views/ppt/utils/speech-player.js`（WebAudio 逐片排期播放 + 逐帧响度 → 口型；分片奇数长度留字节进位；`stop()` 掐掉已排期音源）；
- 前端 PPT 页：接 `BroadcastChannel('tb-meeting:{会议号}')` 播报总线（**单向**：控制台 → 放映页），工具栏加「试听本页」（彩排，念备注区草稿）；
- 前端控制台：「开始演讲 / 停止演讲」改为发总线指令；手输播报框保留，同样走总线；
- 前端会议房间：屏幕共享开 `audio: true`，学生端把 `screen_share_audio` attach 到隐藏 `<audio>`；
- 前端删除：`hooks/usePresenterRoom.js`、`utils/agentAudio.js`、`components/DigitalHumanAvatar.vue`；`utils/workflow-sse.js` 收成通用 `utils/event-stream.js`（工作流与播报共用）。

## 3. 已定决策（不再翻案）

| # | 议题 | 决策 | 理由 |
| --- | --- | --- | --- |
| 1 | 声音从哪出 | **放映页本页** | 学生听到的就是这一页的声音（共享轨自带音频），不存在两条链路对不齐 |
| 2 | 口型来源 | **本页正在播的音频**（同一 AudioContext 取响度） | 与声音天然同步；不再需要「订阅同一条远端轨」 |
| 3 | 传输形态 | **SSE + base64 分片**（与既有工作流 SSE 同一读取器） | 复用已验证的 `fetch + ReadableStream`；断连即取消，不需要 `say/cancel` |
| 4 | 触发通道 | **`BroadcastChannel` 单向**（控制台 → 放映页） | 按钮在控制台、播放在放映页；单向即够 —— 翻页仍由放映页自己说了算 |
| 5 | 采样率 | **48kHz / 单声道 / 16bit**，不重采样 | 与 CosyVoice 出口一致，`AudioContext` 直接吃 |
| 6 | 落库 | 请求带齐 `meetingNo + hostToken` 才以数字人身份落 `lecture_meeting_message`（`kind=2`） | 彩排试听不该出现在会议记录里 |
| 7 | 「开始演讲」语义 | 仍是**开始信号**，本轮内容 mock（`MOCK_LECTURE_TEXT = '你好'`） | 下一轮换成「放映页念当前页 `remark` / AI 现场讲词」时信号不变 |
| 8 | 共享的音频勾选 | **不检测**，靠现象排查（学生听不到 → 提示重新共享） | 勾选由浏览器弹窗决定，脚本既不能代选也无法可靠探测 |

## 4. 测试决策

**后端**（有测试基建，必须写）：`DigitalHumanServiceImplTest` 重写为 11 例 —— 用 `SseEmitter` 的 `send` 层替身锁住 SSE 分帧（`chunk` 必须是**裸 base64 + text/plain**，被 JSON 引号包住会让前端静默无声）、断连时写入抛 IOException 且 `isBroken()`（合成据此取消）、彩排不落库、凭据无效不合成、`status` 只反映配置；`LiveKitTokenServiceTest` / `MeetingServiceImplTest` 删掉 agent/presenter 与 `present` 相关用例。

**前端**：`tests/speech-player.test.js`（8 例）—— 分片进位的采样数、逐帧瞬时响度、`stop()` 掐音源并归零、`destroy()` 才关 AudioContext；`tests/attendees.test.js` 去掉「按身份排除」用例，改钉「房间里的人全部列出」。

**完成定义（实际达成）**：后端 `tb-module-lecture` **47/47**（1 例探针默认跳过）；前端 `npm test` **178/178**；`oxlint` + `eslint` 干净；`vite build` 通过。
**手工验收**：docs/16 §11.2 第 19~22 条 —— 声音从放映页出、学生端听得到、停止立刻停、「试听本页」彩排可用、取消音频勾选时学生听不到。

## 5. 明确不做（含接受的代价）

- **跟页自动照读（A 段）/ AI 现场讲词（B 段）**：本轮「开始演讲」仍是 mock 文本；页码总线不做。
- **翻页遥控**：仍按 docs/18 的口径（页面真相只有一个，控制台不反向指挥）。
- **共享音频勾选的检测与补救**：只写进文档与提示文案。
- **学生端形象**：删掉 `DigitalHumanAvatar.vue` 之后，学生端不再有独立形象 —— 形象只存在于老师共享的画面里（代价，非缺陷）。
- **`digital-human-worker/` 目录的手工删除**：代码与配置已全部摘除，但目录本身因本机回收站策略未能删除，需人工 `Remove-Item -Recurse -Force digital-human-worker`。
- **浏览器自动播放策略**：`AudioContext` 在页面拿到过用户手势前只能挂起 —— 刷新放映页后若直接由控制台触发播报，可能出现「念了但没声音」，需先在该页点一下；本轮不做 UI 提示（写进 docs/16 §5.7 代价④）。
- **共享选源 / 音频勾选的兜底**：不检测、不重试，靠提示文案与现象排查（与 docs/16 §5.6 的手势硬约束同源）。
