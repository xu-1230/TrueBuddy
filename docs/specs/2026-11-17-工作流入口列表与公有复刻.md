# 工作流入口列表与公有复刻（`/index/workflow` 改为「我的 + 公有库」）

日期：2026-11-17 ｜ 模块：`frontend/src/views/workflow2`、`frontend/src/router`、`backend/tb-module-workflow`、`backend/tb-server`
上游规范：[docs/doc.md](../doc.md)、[docs/adr/0006](../adr/0006-知识库与工作流归属与共享模型.md)、[docs/adr/0007](../adr/0007-工作流入口收敛为登录态列表.md)
相关：[docs/doc-workflow.md](../doc-workflow.md)、[docs/doc-api.md](../doc-api.md)、[docs/doc-conventions.md](../doc-conventions.md) §5、[docs/doc-database.md](../doc-database.md) §8

## 1. 问题陈述

工作流的归属 / 公有 / fork 已在 ADR 0006 落地，但前端没有「我的工作流列表」：`/index/workflow` 默认直接渲染一块空白画布，`listWorkflows` 接口前端根本没有消费，用户只能靠带 `?workflow_id=` 的链接打开已保存的工作流；公有库只能从画布右上角的抽屉进入。模块入口与知识库页（空间列表 + 公有库）明显不一致。

## 2. 方案概述

- **入口分层**：`/index/workflow` 为列表；`/index/workflow/:id` 为画布（编辑或只读）；`/index/workflow/new` 为新画布。
- **列表两区**：「我的工作流」（内置模板单列小组 + 用户自建）与「公有库」（他人公有，可只读打开或 fork）。
- **归属与权限**：继续以 ADR 0006 为准；内置模板只读可运行，公有对他人只读、运行须先 fork。
- **登录收紧**：整个 `/index` 要求登录；`/workflow/**` 移出后端免登录白名单（见 ADR 0007）。
- **删除**：本轮补软删除（仅创建者、builtin 拒绝），会话 / 执行记录不级联。
- **只改必要面**：不改表结构（`visibility` / `deleted` 已存在），不改 `/chat` 执行协议。

## 3. 口径（已确认）

| # | 决策 | 结论 |
| --- | --- | --- |
| D1 | 页面结构 | `/index/workflow` 列表；`/index/workflow/:id` 画布；`/index/workflow/new` 新画布 |
| D2 | 旧链接 | `?workflow_id=<id>` 直接废弃，不重定向；落到列表并忽略该参数 |
| D3 | 列表组织 | 上下两区「我的工作流」+「公有库」，与知识库页同构 |
| D4 | 我的工作流 | 内置模板单列小组置顶，用户自建在其下；均按更新时间倒序 |
| D5 | 删除 | `DELETE /workflow/delete?workflow_id=` 软删除；登录必需、仅创建者、builtin 拒绝；会话 / 执行记录保留 |
| D6 | 可见性 | 列表卡片与画布顶部都保留公有/私有切换；builtin 无入口 |
| D7 | 内置模板 | 带「内置」角标；画布只读但可运行；不可保存 / 删除 / 切换可见性 / fork |
| D8 | 新建流程 | 默认链路；显式保存；首次保存 `replace` 到 `/:id`；未保存离开（路由 + 关页签）弹确认 |
| D9 | 公有卡片 | 打开只读画布；「添加为自己的」fork 成功后留在列表并刷新 |
| D10 | 画布内 fork | 只读画布顶部「添加为自己的」→ `replace` 到副本画布 |
| D11 | 公有库入口 | 画布内抽屉与按钮移除，发现入口统一到列表页 |
| D12 | 卡片操作 | 我的：打开 / 可见性 / 删除；builtin：仅打开；公有：打开 / fork |
| D13 | 列表能力 | 不加搜索 / 排序 / 筛选；沿用后端 `update_time DESC`；卡片不提供直接运行 |
| D14 | 登录要求 | 整个 `/index` 要求登录；`/workflow/**` 移出免登录白名单 |
| D15 | 载入失败 | 不存在 / 无权 / 已删除 → toast + `replace` 回列表；断网 / 5xx → 画布区保留「重新载入」 |
| D16 | 归属判定 | 列表卡片可见性以服务端下发的 `visibility` 为准；只读与否以详情 `mine` / `builtin` 为准，前端不猜 |

### 3.1 默认口径

- 列表卡片不展示 `status`（当前没有发布接口，用户工作流恒为草稿）。
- 卡片展示：名称、说明（截断）、`N 个步骤`、更新时间；公有卡片额外展示创建者，我的卡片展示可见性标签。
- 列表页不提供卡片重命名 / 复制；重命名走画布保存对话框。
- 画布「返回列表」`push` 到 `/index/workflow`；未保存时先弹确认。
- 同一路由重复点击做前置比较，避免 redundant navigation。
- 雪花 id 全程按字符串处理，不转数值。

## 4. 验收项

| # | 场景 | 预期 |
| --- | --- | --- |
| AC1 | 登录后打开 `/index/workflow` | 展示「我的工作流」与「公有库」两区；内置模板单独置顶 |
| AC2 | 点自己的卡片 | 进入 `/index/workflow/:id`，画布可编辑、可保存、可运行 |
| AC3 | 点内置模板 | 进入只读画布，顶部标「内置模板」；可运行，保存 / 可见性 / 删除入口不可用 |
| AC4 | 点公有卡片 | 进入只读画布，顶部标「他人公开 · 只读」；运行提示先 fork |
| AC5 | 公有卡片「添加为自己的」 | 留在列表并刷新，「我的工作流」出现「原名（副本）」 |
| AC6 | 只读画布「添加为自己的」 | fork 后 `replace` 到副本画布，副本可编辑 |
| AC7 | 自己的卡片切换公有 / 私有 | 卡片标签立即更新；刷新后保持 |
| AC8 | 删除自己的卡片 | 二次确认后从列表移除；已有会话仍可查，再用它运行报「工作流不存在」 |
| AC9 | 点「新建工作流」 | 进入 `/index/workflow/new`，画布为默认链路 |
| AC10 | 新建后保存 | `replace` 到 `/index/workflow/:id`；返回列表可见该条 |
| AC11 | 新建后未保存点返回 | 弹「放弃本次修改？」；确认后回列表，取消则留在画布 |
| AC12 | 直接访问不存在 / 无权 / 已删除的 `/:id` | toast + `replace` 回列表 |
| AC13 | 断网打开 `/:id` | 画布区显示「载入失败 + 重新载入 + 返回列表」，地址保留 |
| AC14 | 未登录访问任意 `/index/*` | 跳 `/login?redirect=<原地址>`；登录后回跳 |
| AC15 | 匿名直接调用 `/api/workflow/list` | 401 |
| AC16 | 旧地址 `/index/workflow?workflow_id=123` | 停在列表，参数被忽略；不再打开画布 |
| AC17 | 画布内点侧栏「工作流编排」 | 回到列表；画布路由仍保持侧栏高亮 |
| AC18 | 列表页布局 | 使用正常带内边距布局；画布 / 新建页为全幅 |

## 6. 明确不做

- 不做搜索 / 排序 / 筛选、卡片直接运行、卡片重命名 / 复制。
- 不做删除级联、版本管理、表结构变更。
- 不改管理端工作流台账、`/chat` 执行协议、直跑闸与 fork 语义。
- 不把文档选择 / 节点选择等过程态写进 URL。
