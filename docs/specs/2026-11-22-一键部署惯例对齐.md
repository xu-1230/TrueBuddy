## 2. 参考来源与决策

| 来源 | 借鉴点 | 本项目决策 |
| --- | --- | --- |
| Immich 官方 Quick start | 下载 `docker-compose.yml` + `example.env`，手动改 `.env`；人工 smoke test | 我们已内置模板并自动补齐缺失键；进一步自动化健康验证 |
| Gitea 官方文档 | `${VAR:?}` 必填变量、命名卷避免权限问题、固定容器内端口只映射宿主端口 | 采用命名卷与固定容器端口；必填校验放在脚本，不破坏占位启动 |
| Supabase 自托管文档 | `up -d --wait`、`run.sh` 子命令、`generate-keys.sh`、`update.sh`、版本文件 | 采用 `--wait` 与健康检查；新增 `manage.sh/ps1` 与随机凭据生成；不实现自动升级以免误覆盖配置 |

## 3. 关键口径

- 随机生成的凭据仅限本地服务：`POSTGRES_PASSWORD` / `SPRING_DATASOURCE_PASSWORD`（同值）、`MINIO_SECRET_KEY`、`LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET`。
- 外部服务密钥（DeepSeek、DashScope、DocMind、邮件）不生成，也不回显；`env-check` 只列键名。
- 生成条件是值为空或模板占位（`change-me` / `change-me-please` / `postgres`），已有真实值绝不覆盖。
- 后端 healthcheck 使用 `curl http://127.0.0.1:8086/api/homework/task/list`，前端依赖 `service_healthy`。

## 4. 验收项

1. 全新 `.env` 执行部署后，本地服务凭据自动生成且脚本不回显值。
2. `docker compose up -d --wait` 在健康检查通过后返回；`backend` 状态含 `(healthy)`。
3. `bash deploy/manage.sh env-check` 只输出占位键名，不输出任何值。
4. `manage.sh start/stop/restart/recreate/logs/ps/pull` 均可执行。
5. 文档说明与一键脚本实际行为一致。
