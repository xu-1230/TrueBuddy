# 首页「文档」tab 改为生成文档列表

日期：2026-11-16 ｜ 模块：`frontend/src/views/system`、`tb-module-doctemplate`
上游规范：[docs/doc.md](../doc.md) ｜ 需求来源：2026-11-16 用户指定（沿用 `GET /doc-template/history?limit=24`，不新增接口）
相关：[docs/doc-ui.md](../doc-ui.md) §9、[docs/doc-doctemplate.md](../doc-doctemplate.md)、[docs/doc-api.md](../doc-api.md)、[specs/2026-11-16-首页tab与归属共享模型.md](./2026-11-16-首页tab与归属共享模型.md)、[specs/2026-11-16-模板生成页路由状态.md](./2026-11-16-模板生成页路由状态.md)

## 1. 问题陈述

首页 Zone C 的「文档」tab 目前是**跳转型**：点击直接去 `/index/doc-template`，不占用过滤态；Zone D 的 `doc` 卡片实际是**生成任务**（来自 `getGenerationHistory`），点击也只能到生成页基础路径。结果是：

- 首页看不到任何已产出的文档；
- 无法从首页直达「某次生成里的某一份文档」；
- 有产物的任务与失败任务混在同一类卡片里，语义不清。

## 2. 方案概述

- **不新增接口**：扩展 `GET /doc-template/history?limit=`，在每条 `GenerationHistoryRespVO` 内联 `docs`（`DocFileRespVO` 摘要，**不签发 MinIO URL**）。
- **后端一次批量查**：按本次返回的 generation id 集合走 `generation_id IN (...)`，避免逐任务查询的 N+1。
- **文档 tab 改为过滤型**：与综合 / 知识库 / 工作流一致，过滤 Zone D 卡片，不再跳页。
- **一份文件一张卡**：首页把每个 `docs[]` 元素展开为 `kind: 'doc'` 卡片；点击直达 `/index/doc-template/:generationId?file=<doc_template_file.id>`（复用 [模板生成页路由状态](./2026-11-16-模板生成页路由状态.md)）。
- **失败 / 0 份任务不在首页出卡**：它们没有文件；仍可在模板页历史抽屉查看。

> 本 spec 取代 [首页 tab 与归属共享模型](./2026-11-16-首页tab与归属共享模型.md) 的 US3（「文档」tab 跳转）；原 spec 作为过程记录保留不改。

## 3. 口径

| # | 决策 | 结论 |
| --- | --- | --- |
| D1 | 数据源 | 沿用 `GET /doc-template/history?limit=24`；响应新增 `docs` 数组 |
| D2 | `docs` 字段 | `DocFileRespVO`：`id` / `fileId` / `name` / `type` / `size` / `tag` / `summary` / `createTime`；`src` 不填 |
| D3 | 查询方式 | 一次 `SELECT ... WHERE generation_id IN (...)` + 内存分组，禁止逐任务 select |
| D4 | 文档 tab | `type: 'filter'`，key 仍为 `doc`；纳入 `FILTER_TAB_KEYS` 与会话记忆 |
| D5 | 卡片粒度 | 一份文件一张卡；key `doc-file-<fileId>` |
| D6 | 卡片字段 | 标题 = 文件 `name`；描述 = `summary`，缺失回退「来自「任务标题」」；药丸 = `tag`（无则类型名）；数值条 = `本批 <docCount>`；时间 = 文件 `createTime` |
| D7 | 跳转 | `/index/doc-template/<generationId>?file=<file.id>` |
| D8 | 空态 | 文档 tab 显示「去生成文档」→ `/index/doc-template`；知识库 / 工作流 tab 的空态 CTA 一并按 tab 归一 |
| D9 | 失败 / 0 份 | 不产出文件卡；仅模板页历史抽屉可见 |
| D10 | 归属 | 沿用现状：`/doc-template/**` 未按 `creator` 过滤，本次不处理，维持「待整改」 |

## 4. 验收项

| # | 场景 | 预期 |
| --- | --- | --- |
| AC1 | 点首页「文档」tab | 不跳页；`activeTab` 变为 `doc`，Zone D 只剩文件卡 |
| AC2 | 点任一张文件卡 | 跳 `/index/doc-template/:generationId?file=<docId>`，模板页打开对应文档 |
| AC3 | 某次生成有 3 份文件 | 首页出现 3 张卡，均指向同一 `generationId`、不同 `file` |
| AC4 | 失败 / 0 份任务 | 首页无卡片；模板页历史抽屉仍能看到该任务 |
| AC5 | 综合 tab | 文件卡与知识库 / 工作流卡共同出现，按现有排序规则排列 |
| AC6 | `GET /doc-template/history` | 每条记录带 `docs`；`src` 为空；不产生 MinIO 预签名调用 |
| AC7 | 刷新首页 | 文档 tab 的过滤态从 sessionStorage 恢复（`doc` 已在 filter key 内） |

## 6. 明确不做

- 不新增独立文件列表接口，不改 `limit` 的「按任务数」语义。
- 不在 history 响应中签发预签名 URL（避免无用的 MinIO 调用）。
- 不在首页展示失败任务卡；失败诊断仍在模板页历史抽屉。
- 不处理 `creator` 越权过滤（沿用待整改口径）。
- 不改 AssetCard 的结构与样式（数值条继续用 `metric` / `metricLabel` 承载「本批 N」）。
