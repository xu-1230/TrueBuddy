## 1. 前端组件规范

### 1.1 分层

组件按「复用范围」分三层，禁止跨层混放：

| 层级 | 位置 | 判定标准 | 现有示例 |
| --- | --- | --- | --- |
| 全局通用组件 | `src/components/` | 被 ≥2 个模块使用，或属于全局框架（登录、导航） | `LoginForm`、`RegisterForm`、`ForgetPasswordForm`、`LoginShowcase`、`MarkdownViewer`、`NavbarItem`（+ `navbar/menuData.js` 菜单数据） |
| 模块私有组件 | `views/{模块}/components/` | 仅本模块使用 | `DocxPreview`、`SpaceGridView`、`ScreenSlide`、`meeting/components/ChatPanel` |
| 页面内联 | 页面 `.vue` 内部 | 只服务于单个页面、无复用价值 | 页面局部结构 |

> 判定口诀：**先放模块内，出现第二个使用方再上提到 `src/components/`**。

> **实际分层比三层更多**（文档旧口径只列了三层，以下是已存在的扩展层，均属「模块私有」的细分，不得随意上提）：
>
> | 位置 | 用途 | 现有示例 |
> | --- | --- | --- |
> | `views/{模块}/node/` | 画布类模块的节点卡片组件 | `workflow2/node/`（5 个） |
> | `views/{模块}/screen/`、`element/`、`ai/`、`thumbnail/` | PPT 模块的再分层 | `ppt/components/{ai,element,screen,thumbnail}/`、`ppt/screen/` |
> | `views/{模块}/hooks/` | 模块私有组合式函数 | `meeting/hooks/useLiveKitRoom.js`、`ppt/hooks/` |
> | `src/composables/` | **跨模块**组合式函数 | `useSmoothScroll`、`useAppearance`、`useCodeCooldown` |
> | `views/{模块}/stores/` | 模块私有 Pinia store | `ppt/stores/{slides,screen}.js`、`meeting/stores/meeting.js` |
> | `views/{模块}/utils/` | 模块私有纯函数（**优先在此写可测函数**） | `meeting/utils/`、`workflow2/utils/`、`system/utils/feed.js` |
> | `src/lib/` | 跨模块复用的纯函数（无 Vue 依赖） | `particleMorph.js`、`spring.js`、`springTo.js` |
> | `views/{模块}/mock/` | 演示数据，须在文件头标注「演示态」 | `ppt/mock/` |

### 1.2 命名

- 组件文件多单词 **PascalCase**，且必须能表达职责：`DocumentUploadView.vue`、`NodeStatusBadge.vue`。
- 组件名与文件名一致；模板中使用 PascalCase 标签。
- 避免 `index.vue` 之外的通用名（如 `Item.vue`、`Comp.vue`）。

### 1.3 写法

```vue
<script setup>
import { computed, ref } from "vue";

const props = defineProps({
  space: { type: Object, required: true },
  loading: { type: Boolean, default: false },
});

const emit = defineEmits(["back", "delete-document"]);

const title = computed(() => props.space?.name ?? "");
</script>

<template>
  <div class="space-card">
    <h3>{{ title }}</h3>
    <el-button :loading="loading" @click="emit('back')">返回</el-button>
  </div>
</template>

<style scoped>
.space-card {
  padding: 12px;
}
</style>
```

| 项 | 要求 |
| --- | --- |
| Props | `defineProps`，必须声明 `type`；必填用 `required: true`，可选给 `default` |
| Emits | `defineEmits`，事件名 **kebab-case**（`delete-document`） |
| 双向绑定 | 使用 `defineModel`（现有 `ConfigPanel`、`FolderUploader`、`HistoryDrawer` 已采用） |
| 组合式函数 | 模块内 `hooks/` 或全局 `composables/`，命名 `useXxx` |
| 模板 | 不写复杂表达式；列表渲染必须给 `key` |
| 生命周期 | 注册的监听、定时器、第三方实例（Lenis / GSAP / Pixi / LiveKit `Room`）必须在 `onBeforeUnmount` 清理；离会这类「拆毁路径上仍要发出让服务端收到」的请求走 `navigator.sendBeacon`（见 `api/meeting.js`） |

### 1.4 UI 组件来源

- **优先使用 Element Plus**（已全量注册），不重复造轮子：表单用 `el-form` + `el-input`，列表用 `el-table`，弹层用 `el-dialog`，图标统一从 `@element-plus/icons-vue` 具名引入。
- Element Plus 未覆盖的交互（画布、SVG 按钮、节点卡片）才自研，并放入对应模块。
- 不进行自定义组件的全局注册；一律按需 `import`。

### 1.5 样式

- 组件样式一律 `<style scoped>`；全局样式仅限入口声明——即 `App.vue` 与 `main.js` 引入的 `assets/fonts.css` / `assets/theme.css`（详见 [09-样式规范.md](./09-样式规范.md)）。
- 覆盖 Element Plus 内部类时，优先在 `scoped` 内配合 `:deep()`，避免无节制使用非 scoped 样式。

## 2. 后端组件规范

### 2.1 框架组件（starter）

后端「组件」以 **Spring Boot Starter** 形式提供，位于 `tb-framework/`，各自通过 `@AutoConfiguration` 自动装配：

| Starter | 职责 | 关键组件 | 自动装配入口 |
| --- | --- | --- | --- |
| `tb-common` | 基础库（无自动装配） | `CommonResult`、`PageResult`、`ErrorCode`、`ServiceException`、`ServiceExceptionUtil`、`BeanUtils` / `DateUtils` / `CollectionUtils` | — |
| `tb-spring-boot-starter-web` | Web 通用能力 | `GlobalExceptionHandler`、`WebFrameworkUtils`、`WebProperties`（`tb.web`） | `WebAutoConfiguration` |
| `tb-spring-boot-starter-mybatis` | 持久化通用能力 | `BaseDO`、`BaseMapperX`、`DefaultDBFieldHandler`、分页插件 | `MybatisPlusAutoConfiguration`。**现状：没有任何业务模块依赖该 starter**，业务侧用 `mybatis-spring-boot-starter` 注解 SQL，workflow 用 `JdbcTemplate` |
| `tb-spring-boot-starter-security` | 认证与授权 | `SecurityConfig`、`SecurityAutoConfiguration`、`SecurityProperties`（`tb.security`）、`TokenAuthenticationFilter`、`SecurityFrameworkUtils`、`LoginUser` | `SecurityConfig` / `SecurityAutoConfiguration` |

约定：

- 框架 starter **不感知业务**，不得 import 任何 `module.*` 包。
- Starter 通过 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 暴露自动装配，业务模块只加依赖即可生效。
- 配置一律走 `@ConfigurationProperties`（前缀 `tb.*`），禁止在 starter 内写死业务值。

### 2.2 业务模块内组件

业务模块内部的「可复用单元」按职责归位，不额外引入组件框架：

| 类型 | 形态 | 位置 | 示例 |
| --- | --- | --- | --- |
| 网关 / 外部能力适配 | 接口 + `Impl` | `service/` | `DocxMcpGateway` / `DocxMcpGatewayImpl` |
| 解析网关组件 | 接口 + 网关实现 + 配置 | `service/parse/` | `DocumentParseGateway` + `ParseGatewayConfiguration` + `parse/docmind/DocMindParseGateway` |
| 分片策略组件 | 接口 + 策略实现 | `service/chunk/` | `DocumentChunkService` + `AiDocumentChunkService` |
| 实时通道适配 | 服务类（自签令牌 / 调 RoomService） | `livekit/` | `LiveKitTokenService`（Hutool 手写 HS256）、房间删除 |
| 语音合成与流式播报 | 接口 + `Impl`，按能力再分子包 | `digital/`、`digital/tts/` | `DigitalHumanServiceImpl`（把 PCM 以 SSE 推给放映页，断连即取消合成）、`CosyVoiceTtsSynth`（DashScope WebSocket 流式合成 PCM） |
| 可执行图节点 | 节点类 + 工厂 + 事件监听 | `node/`（`textflow`） | `WorkflowGraphFactory`、`LlmNode`、`HumanNode`、`IterateNode`、`NodeStateReader` |
| SSE 发布器 | 单类封装一帧一事件 | `sse/`（`textflow`） | `ChatSsePublisher` |
| 仓储 | `JdbcTemplate` 手写 SQL | `repository/`（`textflow`） | `WorkflowDefinitionRepository`、`WorkflowRunRepository`、`WorkflowConversationRepository` |
| 提示词资源 | 常量类 | `prompt/` | `AiPromptConstants`、`lecture/ppt/prompt/` |
| 类型处理器 | MyBatis `TypeHandler` | `mybatis/handler/` | `JsonListTypeHandler`、`JsonMapTypeHandler` |
| 模块配置 | `@Configuration` / `@ConfigurationProperties` | `config/` | `MinioConfig`、`AiChatClientConfiguration`、`DocTemplateProperties`、`DocMindProperties`、`MeetingProperties`（`tb.lecture.meeting`）、`DigitalHumanProperties`（`tb.lecture.digital-human`） |

### 2.3 约束

- 跨模块复用**只允许依赖对方的 `service` 接口**（如 `doctemplate` → `knowledgebase`、`infra`），禁止直接依赖实现类、Mapper 或 DO。
- 通用能力优先沉淀到 `tb-framework`，禁止在多个业务模块里重复实现同一工具。
- 组件命名体现职责：`XxxGateway`（外部网关）、`XxxService`（业务能力）、`XxxBuilder`（构造器）、`XxxProperties`（配置）。
