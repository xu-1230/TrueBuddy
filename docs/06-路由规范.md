## 1. 前端路由规范

### 1.1 模式与写法

| 项 | 要求 |
| --- | --- |
| 模式 | `createWebHistory(import.meta.env.BASE_URL)`（HTML5 History） |
| 加载 | **全部**路由组件使用动态 `import()` 懒加载 |
| 配置位置 | 统一在 `src/router/index.js`，不散落到模块 |
| 嵌套 | 布局页作为父路由，功能页作为 `children` |
| 默认跳转 | 布局路由使用 `redirect` 指向默认子页 |
| 命名 | `name` 用 kebab-case（`system-home`、`doc-template`） |
| 路径 | 小写 + 中划线（`knowledge-base`、`homework-grading`）；与 `name` 保持一致 |

```js
{
  path: "/index",
  name: "index",
  component: () => import("../views/IndexView.vue"),
  redirect: "/index/home",
  children: [
    { path: "home", name: "system-home", component: () => import("../views/system/SystemHomeView.vue") },
    { path: "knowledge-base", name: "knowledge-base", component: () => import("../views/knowledgebase/KnowledgeBaseView.vue") },
  ],
}
```

### 1.3 页面文件与路由的对应

- 页面文件统一放 `views/`，**目录层级与路由层级对应**：`/index/knowledge-base` → `views/knowledgebase/`。
- 一个业务模块一个目录；模块私有组件、mock、utils 与其页面同目录（见 [03-项目结构.md](./03-项目结构.md) §3.3）。
- 纯展示页（如 `/login`、`/register` 复用同一组件）允许一条路由映射多个 `path`。

### 1.4 规划与待整改

| 项 | 现状 | 规范要求 / 规划 |
| --- | --- | --- |
| `/guides` 与 `/docs` | 两条**平级**顶层路由，`/guides` 无 `children` | 如需共享顶栏，可改为布局路由 + `children`（`docs` 用相对路径）；细节见 [14-前端 guides 模块全流程.md](./14-前端%20guides%20模块全流程.md) §2.1 |
| 路由守卫 | 管理端已实现 `beforeEach`（Token + `requiresAdmin`）；用户端仍无校验 | 规划：用户端补 `meta.requiresAuth`，未登录跳 `/login` |
| 404 兜底 | 已实现 `/:pathMatch(.*)*` → `views/error/NotFoundView.vue` | 保持 |
| 权限控制 | 管理端菜单按 `meta.permission` 与服务端返回的 `permissions` 过滤，入口权限为 `admin:dashboard`；`granted` / `denied` / `offline` 三态分开处理；用户端无身份控制 | 规划：用户端按普通 / 会员身份控制菜单与页面可达性 |
| 菜单来源 | 用户端在 `IndexView.vue` 内写死 `menuGroups`；管理端由 `admin.routes.js` 的 `meta` 生成 | 管理端新增页面只改路由表一处；用户端维持现状 |

## 2. 后端路由（Controller 映射）规范

### 2.1 映射约定

| 项 | 要求 |
| --- | --- |
| 类级 | `@RestController` + `@RequestMapping("/{模块}/{资源}")`，作为统一前缀 |
| 方法级 | `@GetMapping` / `@PostMapping` / `@PutMapping` / `@DeleteMapping` 声明具体动作 |
| 上下文路径 | `server.servlet.context-path = /api` **不计入** Controller 映射，仅出现在完整 URL 中 |
| 路径命名 | 小写 + 中划线（`/knowledge-base`、`/doc-template`） |
| 资源命名 | 名词复数或集合名（`space`、`document`、`chunk`、`file`） |
| 禁止 | 不在类级映射中写 `/api` 前缀；不使用大写字母与下划线 |

### 2.2 现有映射前缀

| Controller | 类级映射 | 完整前缀 |
| --- | --- | --- |
| `TestController` | `/test` | `/api/test` |

| `Test2Controller` | `/test2` | `/api/test2` |
| `FileController` | `/infra/file` | `/api/infra/file` |

| `HomeworkController` | `/homework` | `/api/homework` |

具体接口路径清单见 [05-API规范.md](./05-API规范.md) §2.5。

### 2.3 路径风格说明

- 项目现状采用「**前缀 + 动作**」风格（`/space/create`、`/space/update`、`/space/delete`、`/document/upload`）。
- 规范要求：**同一 Controller 内保持一致**；新增模块优先使用 REST 资源风格（`POST /knowledge-base/space`、`PUT /knowledge-base/space/{id}`、`DELETE /knowledge-base/space/{id}`）。
- 非 CRUD 的动作（`generate`、`vectorize`、`read-pptx`、`ping`）允许动词式路径，但必须语义明确。

## 3. 路由与安全的对应

后端路由白名单与前端路由守卫需**成对维护**：

| 后端放行 URL（`application.yml`） | 前端对应 |
| --- | --- |
| `/system/auth/login` | `/login`、`/register` |
| `/system/auth/refresh` | 无独立页面；前端 401 拦截器自动调用，不跳路由 |
| `/test2/read-pptx` | 仅测试用途，无正式页面 |
| `/test2/file-text` | 仅联调桩（作业文件文本抽取），无正式页面 |
| `/doc-template/**` | `/index/doc-template` |
| `/homework/**` | `/index/homework-grading`（上传与批改提交，便于未登录态联调） |
| `/workflow/**` | `/index/workflow` 画布页的定义类调用（保存 / 打开 / 列表）。**该前缀下已无 SSE**：执行入口 `POST /chat` 不在白名单内，需登录；也没有轮询兜底（`GET /workflow/get_process` 从未实现） |
| `/meeting/**` | `/meeting/:meetingNo`（学生会议室：免登录入会）、`/index/meeting`（老师控制台，用 `hostToken` 鉴权）。实时媒体与聊天不经过本服务 |
| `/ppt/**` | `/index/ppt`（讲稿生成：两个 AI 按钮 → `POST /ppt/speech/optimize`） |
| `/admin/**`（仅身份接口已实现） | `/admin/**` 管理端页面。`GET /admin/auth/profile`、`GET /admin/auth/permissions` 已按 `admin:dashboard` 做服务端鉴权；其余业务接口仍为前端 mock。前端守卫只负责界面可达性，真正的安全边界在后端 |

> 新增免登录接口时，需同步 [05-API规范.md](./05-API规范.md) §2.4 与 [08-通用约束.md](./08-通用约束.md) §4。
