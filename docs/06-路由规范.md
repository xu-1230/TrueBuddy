## 1. 前端路由规范

### 1.1 模式与写法

| 项 | 要求 |
| --- | --- |
| 模式 | `createWebHistory(import.meta.env.BASE_URL)`（HTML5 History） |
| 加载 | **全部**路由组件使用动态 `import()` 懒加载 |
| 配置位置 | 统一在 `src/router/index.js`，不散落到模块 |
| 嵌套 | 布局页作为父路由，功能页作为 `children` |
| 默认跳转 | 布局路由使用 `redirect` 指向默认子页 |
| 命名 | `name` 用 kebab-case（`system-home`、`doc-template`） |
| 路径 | 小写 + 中划线（`knowledge-base`、`homework-grading`）；与 `name` 保持一致 |

```js
{
  path: "/index",
  name: "index",
  component: () => import("../views/IndexView.vue"),
  redirect: "/index/home",
  children: [
    { path: "home", name: "system-home", component: () => import("../views/system/SystemHomeView.vue") },
    { path: "knowledge-base", name: "knowledge-base", component: () => import("../views/knowledgebase/KnowledgeBaseView.vue") },
  ],
}
```

### 1.2 实际路由表 — `src/router/index.js`

| 路径 | name | 组件（懒加载） | 说明 |
| --- | --- | --- | --- |
| `/guides` | `guides` | `views/guides/HomeView.vue` | 首页（含顶部导航），顶层路由、无 `children` |
| `/docs` | `docs` | `views/guides/DocsView.vue` | 文档 / 登录展示页，与 `/guides` 同级 |
| `/login` | `login` | `views/LoginView.vue` | 登录页 |
| `/register` | `register` | `views/LoginView.vue` | 注册页（复用登录页组件） |
| `/index` | `index` | `views/IndexView.vue` | 侧边栏布局，`redirect` → `/index/home` |
| `/index/home` | `system-home` | `views/system/SystemHomeView.vue` | 系统首页（占位） |
| `/index/doc-template` | `doc-template` | `views/doctemplate/DocTemplateView.vue` | 文档模板生成 |
| `/index/homework-grading` | `homework-grading` | `views/homework/HomeworkGradingView.vue` | 作业批改 |
| `/index/homework-workflow` | `homework-workflow` | `views/homework/HomeworkWorkflowView.vue` | 工作流批改实测（SSE 实时推送执行状态，断线自动轮询） |
| `/index/knowledge-base` | `knowledge-base` | `views/knowledgebase/KnowledgeBaseView.vue` | 知识库 |
| `/index/ppt` | `ppt` | `views/ppt/index.vue` | PPT 预览与放映；**`?screen=1` 时加载后直接进入放映状态**（模拟会议建会后自动打开的那个放映页用；首屏无用户手势，浏览器会拒绝自动全屏，需真全屏时点放映工具条的全屏按钮）。页内含 AI 备注优化：备注区右上角星形按钮（本页）+ 工具栏「AI 优化全部备注」与「本场时长」，结果先弹对比窗再写回 `remark` |
| `/index/meeting` | `meeting-console` | `views/meeting/MeetingConsoleView.vue` | 模拟会议：老师控制台（建会 / 复制入会链接 / 成员与聊天 / 屏幕共享）。**`?meetid={会议号}` 表示「管理这一场」**：建会成功后自动写入地址栏，刷新 / 复制 / 另开标签页都能恢复；不带参数是建会态（并列出本机还留着主持人凭据的会议） |
| `/index/workflow` | `workflow` | `views/workflow/WorkflowView.vue` | 工作流编排 |
| `/meeting/:meetingNo` | `meeting-room` | `views/meeting/MeetingRoomView.vue` | 学生会议室：**顶层路由、不使用 `/index` 布局**、免登录（学生点入会链接直接进入，弹窗输名字） |
| `/test` | `test` | `views/TestView.vue` | 接口连通性 / 身份测试页 |

### 1.3 页面文件与路由的对应

- 页面文件统一放 `views/`，**目录层级与路由层级对应**：`/index/knowledge-base` → `views/knowledgebase/`。
- 一个业务模块一个目录；模块私有组件、mock、utils 与其页面同目录（见 [03-项目结构.md](./03-项目结构.md) §3.3）。
- 纯展示页（如 `/login`、`/register` 复用同一组件）允许一条路由映射多个 `path`。

### 1.4 规划与待整改

| 项 | 现状 | 规范要求 / 规划 |
| --- | --- | --- |
| `/guides` 与 `/docs` | 两条**平级**顶层路由，`/guides` 无 `children` | 如需共享顶栏，可改为布局路由 + `children`（`docs` 用相对路径）；细节见 [14-前端 guides 模块全流程.md](./14-前端%20guides%20模块全流程.md) §2.1 |
| 路由守卫 | 无 `beforeEach`、无 `meta` | 规划：`meta.requiresAuth` + Token 校验，未登录跳 `/login` |
| 404 兜底 | 无 | 规划：新增 `/:pathMatch(.*)*` 兜底路由 |
| 权限控制 | 无 | 规划：按身份（普通 / 会员 / 管理员）控制菜单与路由可达性 |

## 2. 后端路由（Controller 映射）规范

### 2.1 映射约定

| 项 | 要求 |
| --- | --- |
| 类级 | `@RestController` + `@RequestMapping("/{模块}/{资源}")`，作为统一前缀 |
| 方法级 | `@GetMapping` / `@PostMapping` / `@PutMapping` / `@DeleteMapping` 声明具体动作 |
| 上下文路径 | `server.servlet.context-path = /api` **不计入** Controller 映射，仅出现在完整 URL 中 |
| 路径命名 | 小写 + 中划线（`/knowledge-base`、`/doc-template`） |
| 资源命名 | 名词复数或集合名（`space`、`document`、`chunk`、`file`） |
| 禁止 | 不在类级映射中写 `/api` 前缀；不使用大写字母与下划线 |

### 2.2 现有映射前缀

| Controller | 类级映射 | 完整前缀 |
| --- | --- | --- |
| `TestController` | `/test` | `/api/test` |
| `IdentityController` | `/identity` | `/api/identity` |
| `AuthController` | `/system/auth` | `/api/system/auth` |
| `Test2Controller` | `/test2` | `/api/test2` |
| `FileController` | `/infra/file` | `/api/infra/file` |
| `DocTemplateController` | `/doc-template` | `/api/doc-template` |
| `KbSpaceController` | `/knowledge-base/space` | `/api/knowledge-base/space` |
| `KbDocumentController` | `/knowledge-base/document` | `/api/knowledge-base/document` |
| `KbDocumentChunkController` | `/knowledge-base/chunk` | `/api/knowledge-base/chunk` |
| `WorkflowController` | `/workflow` | `/api/workflow` |
| `MeetingController` | `/meeting` | `/api/meeting`（实时媒体与聊天走自托管 LiveKit 的 `7880`/`7881`，不经过本服务的 Controller） |

具体接口路径清单见 [05-API规范.md](./05-API规范.md) §2.5。

### 2.3 路径风格说明

- 项目现状采用「**前缀 + 动作**」风格（`/space/create`、`/space/update`、`/space/delete`、`/document/upload`）。
- 规范要求：**同一 Controller 内保持一致**；新增模块优先使用 REST 资源风格（`POST /knowledge-base/space`、`PUT /knowledge-base/space/{id}`、`DELETE /knowledge-base/space/{id}`）。
- 非 CRUD 的动作（`generate`、`vectorize`、`read-pptx`、`ping`）允许动词式路径，但必须语义明确。

## 3. 路由与安全的对应

后端路由白名单与前端路由守卫需**成对维护**：

| 后端放行 URL（`application.yml`） | 前端对应 |
| --- | --- |
| `/system/auth/login` | `/login`、`/register` |
| `/test2/read-pptx` | 仅测试用途，无正式页面 |
| `/doc-template/**` | `/index/doc-template` |
| `/workflow/**` | `/index/workflow`（画布页：保存 / 打开 / 试运行，已接线 SSE 提交 / 恢复与轮询兜底） |
| `/meeting/**` | `/meeting/:meetingNo`（学生会议室：免登录入会）、`/index/meeting`（老师控制台，用 `hostToken` 鉴权）。实时媒体与聊天不经过本服务 |
| `/ppt/**` | `/index/ppt`（讲稿生成：两个 AI 按钮 → `POST /ppt/speech/optimize`） |

> 新增免登录接口时，需同步 [05-API规范.md](./05-API规范.md) §2.4 与 [08-通用约束.md](./08-通用约束.md) §4。
