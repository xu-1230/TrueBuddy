01

设计原则

五条原则决定「什么可以被调整」：其余细节一律由 Token 派生，避免各模块各造一套。

P1

排版优先

大字号对比 + 衬线 display 承担「气质」，控件本身保持克制。标题字重与字距由 --tb-weight-display / --tb-tracking-display 统一。

P2

单主色关系

主色只用于「可操作」，强调色只用于「数据」，装饰一律交给中性色。同屏主色面积不超过 15%。

P3

形态即性格

圆角、描边宽度、阴影与缓动由主题决定，组件不得自定义：从 Ember 的柔圆到 Void 的直角， 形态本身就是主题的名字。

P4

动效克制

只动 transform / opacity，业务页不做入场编排；展示页用 scroll 编排并尊重 prefers-reduced-motion。

P5

无障碍兜底

正文对比度 ≥ 4.5:1、非文字控件 ≥ 3:1；全局保留 :focus-visible 焦点环，不以颜色单独承载状态。

注

本文件与本项目既有实现的关系：主页 views/guides/HomeView.vue 的暗场橙红大字号即 Ember 的展示态；doctemplate / homework / knowledgebase 的亮场橙红为其业务态； views/ppt（#5b9bd5）与 views/workflow（Arco 蓝灰）收敛为 Ink。 即：三套既有视觉语言对应前三套主题，其余四套（Neon / Moss / Clay / Void）为可选拓展方案， 切换后可整站换肤而无需改动组件。

02

主题总览

七套主题共用同一套语义变量名，只替换「原始色板」与「形态个性」。画廊中每张卡片的根节点都挂着自己的 data-theme，因此能在同一屏内并排对照；页面其余部分的主题由左导轨切换。 卡片里的圆角、描边、阴影与动效数值均从该主题的 CSS 变量实时读出，不存在手工抄写的色号与尺寸。

主题索引（主色为亮色下的 live 计算值）
主题 定位 主色 适用场景 形态个性
规范

模块级主题不得污染全局：PPT 模块的幻灯片配色由幻灯片数据驱动，与 UI 主题分离； 如需局部换肤，在模块根容器上挂 data-theme 即可（本页画廊的七张对照卡即如此实现）。 新增主题只需补一段 [data-theme="…"] 变量块与一条元数据，其余全部自动生效。

约束

只对 transform / opacity 做动画； 禁止高频动画 width / height / top / left。 业务页面（表单、表格、画布）不加入场编排；展示页的滚动动效统一走 composables/useSmoothScroll.js，并在卸载时 kill 掉 ScrollTrigger。

5.6 形态参数对照 · 全主题

七套主题的全部形态差异都收敛在下表；数值从各自的 CSS 变量实时读出，因此永远不会与上面的标本脱节。 除这些值以外，组件不得引入新的形态数值。

边界

--tb-border-width 只作用于组件轮廓（按钮、输入框、卡片、节点卡）； 分隔线、表格行线、页签指示线恒为 1px 细线——这是刻意的分工，避免「处处粗框」。
