## 1. 前端状态管理（Pinia）

### 1.1 组织原则

| 原则 | 说明 |
| --- | --- |
| 局部优先 | 仅单个组件使用的状态用 `ref` / `reactive`，**不得**提升为全局 store |
| 就近放置 | 仅单个业务模块使用的状态放 `views/{模块}/stores/`；跨模块共享才放 `src/stores/` |
| 组合式优先 | 新 store 一律使用 **setup 写法**（`defineStore(id, () => {...})`） |
| 单一职责 | 一个 store 只管理一类状态（如「幻灯片数据」与「放映状态」分离） |
| 命名 | store id 用 kebab-case（`ppt-slides`）；导出的 `useXxxStore` 用 PascalCase |

### 1.2 写法示例

```js
import { computed, ref } from "vue";
import { defineStore } from "pinia";

export const useUserStore = defineStore("user", () => {
  const token = ref("");
  const isLogin = computed(() => Boolean(token));

  function setToken(value) {
    token.value = value;
  }

  return { token, isLogin, setToken };
});
```

> 组件中使用：`const user = useUserStore()`；解构需配合 `storeToRefs` 保持响应性。

### 1.5 持久化

| 键 | 位置 | 用途 |
| --- | --- | --- |
| `token`（Cookie） | `src/utils/auth.js` | 登录态 Token，请求拦截器读取 |
| `tb-homework-workflows` | `views/homework/utils/workflows.js` | 批改工作流配置（演示态） |
| `tb-homework-history-demo` | `views/homework/mock/grading.js` | 批改历史（演示态） |

约定：

- **登录态只由 `utils/auth.js` 管理**，禁止组件自行读写 Token（`views/TestView.vue` 额外写 `localStorage` 属待整改）。
- 演示态数据持久化必须使用带业务前缀的键名（`tb-{模块}-{用途}`），并在注释中标注「演示态」。
- 规划：需要长期保留的业务状态改用 Pinia 插件（如 `pinia-plugin-persistedstate`）统一处理，避免散落的 `localStorage` 调用。

## 2. 后端会话与请求上下文

### 2.1 无状态会话

| 项 | 约定 |
| --- | --- |
| 会话策略 | `SessionCreationPolicy.STATELESS`，**不使用 `HttpSession`** |
| CSRF | 关闭（无状态 + Token 认证） |
| 认证载体 | Token（请求头 `Authorization: Bearer <token>`，或参数 `token`） |
| 用户上下文 | 由 `TokenAuthenticationFilter` 解析 Token → 构造 `LoginUser` → 写入 `SecurityContext` |

### 2.2 上下文获取

```java
LoginUser loginUser = SecurityFrameworkUtils.getLoginUser();
```

| 组件 | 位置 | 职责 |
| --- | --- | --- |
| `TokenAuthenticationFilter` | `framework.security.core.filter` | 提取 Token、校验、写入 `LoginUser` |
| `SecurityFrameworkUtils` | `framework.security.util` | `obtainAuthorization` / `getLoginUser` / `setLoginUser` |
| `LoginUser` | `framework.security` | 持有 `id` / `userType` / `info` / `scopes` / `expiresTime` |
| `UserTypeEnum` | `framework.common.enums` | `NORMAL(0)` / `MEMBER(1)` / `ADMIN(2)` |

约定：

- 业务代码**不得**自行解析 Token 或从请求参数直接取 `userId`，一律通过 `SecurityFrameworkUtils` 获取当前登录用户。
- 方法级鉴权使用 `@EnableMethodSecurity` 已启用的能力（`@PreAuthorize` 等）；当前项目仅在身份验证接口中通过 `UserTypeEnum` 比较实现。
- 身份不匹配由过滤器抛 `AccessDeniedException`，最终由安全组件返回未授权响应。
- 有效期配置走 `@Value` 默认值（访问令牌 7200s / 刷新令牌 604800s），未在 `application.yml` 中显式声明；规划统一收敛到 `@ConfigurationProperties`。

### 2.3 规划

| 项 | 规划 |
| --- | --- |
| JWT | 当前 Token 校验为占位实现，规划签发标准 JWT |
| 令牌存储 | 由数据库表（`system_oauth2_access_token` / `system_oauth2_refresh_token`）承载 |
| 刷新机制 | 规划刷新令牌续期接口 |
