## 1. 前端状态管理（Pinia）

### 1.1 组织原则

| 原则 | 说明 |
| --- | --- |
| 局部优先 | 仅单个组件使用的状态用 `ref` / `reactive`，**不得**提升为全局 store |
| 就近放置 | 仅单个业务模块使用的状态放 `views/{模块}/stores/`；跨模块共享才放 `src/stores/` |
| 组合式优先 | 新 store 一律使用 **setup 写法**（`defineStore(id, () => {...})`） |
| 单一职责 | 一个 store 只管理一类状态（如「幻灯片数据」与「放映状态」分离） |
| 命名 | store id 用 kebab-case（`ppt-slides`）；导出的 `useXxxStore` 用 PascalCase |

### 1.2 写法示例

```js
import { computed, ref } from "vue";
import { defineStore } from "pinia";

export const useUserStore = defineStore("user", () => {
  const token = ref("");
  const isLogin = computed(() => Boolean(token));

  function setToken(value) {
    token.value = value;
  }

  return { token, isLogin, setToken };
});
```

> 组件中使用：`const user = useUserStore()`；解构需配合 `storeToRefs` 保持响应性。

### 1.3 现有 store 分布

**没有 `src/stores/` 目录**（脚手架示例 `counter.js` 已删除）；store 一律放在所属模块内：

| 位置 | store id | 状态 | getters | actions | 写法 |
| --- | --- | --- | --- | --- | --- |
| `views/meeting/stores/meeting.js` | `meeting` | `meeting`、`roomAttendees`、`messages`、`sharing`、`connection`、`ended`、`selfIdentity` | `connected`、`memberPanel`（降级时空名单且不给人数） | `applyEvent`（实时事件唯一入口）、入会/离会时的状态重置 | **setup** |
| `views/ppt/stores/slides.js` | `ppt-slides` | `theme`、`slides`、`slideIndex`、`viewportRatio` | `currentSlide`、`currentSlideAnimations`、`formatedAnimations`（代码里的原名如此，拼写待随整改统一） | `setTheme`、`setViewportRatio`、`setSlides`、`addSlide`、`updateSlide`、`deleteSlide`、`updateSlideIndex`、`addElement`、`deleteElement`、`updateElement` | options |
| `views/ppt/stores/screen.js` | `ppt-screen` | `screening` | — | `setScreening` | options |

> `meeting` store 的设计约束（改会议页前必读）：成员**只有一份** `roomAttendees`，来自 LiveKit 房间事件（[adr/0002](./adr/0002-在线状态唯一真相源为房间事件.md)）；REST `detail` / `state` 返回的 `attendees` 是累计入会台账，前端**不消费**它。消息归属判定用 store 注入的 `selfIdentity`，不在组件里比对 `attendeeId`。

### 1.5 持久化

| 键 | 存储 | 位置 | 用途 |
| --- | --- | --- | --- |
| `token`（Cookie） | Cookie | `src/utils/auth.js` | 登录态 Token，请求拦截器读取 |
| `tb-ui-mode` | localStorage | `composables/useAppearance.js` | 明暗态（`null` 表示跟随系统） |
| `tb-meeting-host:{meetingNo}` | localStorage | `views/meeting/MeetingConsoleView.vue` | **按会议号切分**的主持人凭据台账：控制台刷新/另开标签页恢复「管理这一场」，并列出本机还留有凭据的会议 |
| `tb-meeting-host` | sessionStorage | 同上（`LEGACY_SESSION_KEY`） | 旧格式单键，读到即迁移一次后不再使用 |
| `tb-meeting-attendee-{meetingNo}` | sessionStorage | `views/meeting/MeetingRoomView.vue` | 参会会话（`attendeeToken` / `attendeeId` / `nickname`），刷新免二次输名并用它重新取令牌 |
| ~~`tb-homework-workflows`~~ / ~~`tb-homework-history-demo`~~ | — | 已删除 | 演示态键随 `homework/utils/workflows.js`、`homework/mock/grading.js` 一起下线 |

约定：

- **登录态只由 `utils/auth.js` 管理**，禁止组件自行读写 Token（`views/TestView.vue` 额外写 `localStorage` 属待整改）。
- **会议凭据不是登录态**：`hostToken` / `attendeeToken` 刻意不进 `auth.js`、不进 Cookie，key 必须带会议号；学生侧用 sessionStorage（关标签页即弃），老师侧用 localStorage（跨会话管理自己的会）。
- 键名统一 `tb-{模块}-{用途}` 前缀；演示态数据须在注释中标注「演示态」。
- 规划：需要长期保留的业务状态改用 Pinia 插件（如 `pinia-plugin-persistedstate`）统一处理，避免散落的 `localStorage` 调用。

## 2. 后端会话与请求上下文

### 2.1 无状态会话

| 项 | 约定 |
| --- | --- |
| 会话策略 | `SessionCreationPolicy.STATELESS`，**不使用 `HttpSession`** |
| CSRF | 关闭（无状态 + Token 认证） |
| 认证载体 | Token（请求头 `Authorization: Bearer <token>`，或参数 `token`） |
| 用户上下文 | 由 `TokenAuthenticationFilter` 解析 Token → 构造 `LoginUser` → 写入 `SecurityContext` |

### 2.2 上下文获取

```java
LoginUser loginUser = SecurityFrameworkUtils.getLoginUser();
```

| 组件 | 位置 | 职责 |
| --- | --- | --- |
| `TokenAuthenticationFilter` | `framework.security.core.filter` | 提取 Token、校验、写入 `LoginUser` |
| `SecurityFrameworkUtils` | `framework.security.util` | `obtainAuthorization` / `getLoginUser` / `setLoginUser` |
| `LoginUser` | `framework.security` | 持有 `id` / `userType` / `info` / `scopes` / `expiresTime` |
| `UserTypeEnum` | `framework.common.enums` | `NORMAL(0)` / `MEMBER(1)` / `ADMIN(2)` |

约定：

- 业务代码**不得**自行解析 Token 或从请求参数直接取 `userId`，一律通过 `SecurityFrameworkUtils` 获取当前登录用户。
- 方法级鉴权：`SecurityConfig` 上已开 `@EnableMethodSecurity(securedEnabled = true)`，但**全仓当前 0 处** `@PreAuthorize` / `@Secured` 用法；身份判定实际靠 `tb-module-test` 的 `IdentityController` 内部比较 `UserTypeEnum`。
- 身份不匹配由过滤器抛 `AccessDeniedException`，最终由安全组件返回未授权响应。
- 有效期配置走 `@Value` 默认值（访问令牌 7200s / 刷新令牌 604800s），未在 `application.yml` 中显式声明；规划统一收敛到 `@ConfigurationProperties`（与 [02](./02-编码规范.md) §3.3「禁止散落 `@Value`」冲突，已记为待整改）。
- 会议凭据（`hostToken` / `attendeeToken`）**不走** Spring Security：它们是业务侧字符串比对，与登录态 `LoginUser` 无关。

### 2.3 规划

| 项 | 规划 |
| --- | --- |
| JWT | 当前 Token 校验为占位实现，规划签发标准 JWT |
| 令牌存储 | 由数据库表（`system_oauth2_access_token` / `system_oauth2_refresh_token`）承载 |
| 刷新机制 | 规划刷新令牌续期接口 |
