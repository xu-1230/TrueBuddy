```

│   ├── tb-spring-boot-starter-web/        # Web 组件（全局异常、CORS，自动装配）
│   ├── tb-spring-boot-starter-mybatis/    # MyBatis Plus 组件（BaseDO / BaseMapperX / 审计填充）
│   └── tb-spring-boot-starter-security/   # 安全组件（Security 配置 / TokenAuthenticationFilter）
├── tb-module-test/                # 连通性 + 登录鉴权 + 身份校验
├── tb-module-test2/               # 文档解析验证（pptx 读取 / 文档智能原始结果调试）
├── tb-module-infra/               # 基础设施：通用文件上传（MinIO）+ infra_file 元数据
```

```
│   ├── web/                       # 全局异常处理、CORS、自动配置
│   ├── mybatis/                   # BaseDO / BaseMapperX / 分页插件 / 审计填充

    ├── test2/                     # controller / service
    ├── infra/                     # controller / service(+Impl) / mapper / model(+vo) / config / enums
    ├── knowledgebase/             # controller / service(+Impl) / service.chunk / service.parse(+docmind)

    └── doctemplate/               # controller / service(+Impl) / mapper / model(+vo) / config / enums / prompt
```

`knowledgebase` 是当前结构最完整的模块，可作为新模块的样板（详见 [03-项目结构.md](../docs/03-项目结构.md) §2.3）。

### 2.2 分层约定

| 层 | 职责 | 位置 |
|----|------|------|
| Controller | 接收请求、参数校验、返回 `CommonResult<T>` | `module/{m}/controller/` |
| Service | 业务逻辑、事务控制（接口 + Impl 分离） | `module/{m}/service/`、`service/Impl/` |
| DO | 数据库实体（`@Data` POJO，字段 camelCase 映射下划线列） | `module/{m}/model/` |
| Mapper | 数据访问（`@Mapper` 接口 + 注解 SQL） | `module/{m}/mapper/` |
| VO | 接口出入参对象（`XxxReqVO` / `XxxRespVO`） | `module/{m}/model/vo/` |

> 分层单向依赖：Controller → Service → Mapper，禁止反向依赖。DO 禁止暴露到接口层，接口出入参一律使用 VO。

> **现状说明（与框架组件的差异）**：`tb-spring-boot-starter-mybatis` 提供了 `BaseDO` / `BaseMapperX`，但**业务模块当前未使用**——各模块 DO 为普通 POJO，Mapper 为原生 MyBatis `@Mapper` 接口 + 注解 SQL（如 `KbDocumentMapper`）。框架组件能力保留待后续统一接入。

## 3. 开发规范

| 规范 | 要求 |
|------|------|
| 模块划分 | 业务模块为单模块（如未来创建的 `tb-module-system`），不拆分 api/biz；当前尚未创建，`-biz` 仅用于框架 starter 命名 |
| Controller | `@RestController`，返回统一 `CommonResult` |
| Service | 接口 + Impl 分离，实现类标注 `@Service` |
| DO | `@Data` POJO，字段 camelCase 对应下划线列；主键 `Long id`（数据库 `GENERATED BY DEFAULT AS IDENTITY`） |
| Mapper | `@Mapper` 接口 + `@Select` / `@Insert` / `@Update` / `@Delete` 注解 SQL，无 XML 文件 |
| 配置 | `application.yml`（位于 `tb-server`），敏感信息通过环境变量注入 |
| SQL | 单表读写用注解 SQL；动态语句（如批量插入）用 `<script>` + `<foreach>`；复杂查询可下沉到 XML（当前无 XML） |
| 命名 | 类名 PascalCase，方法/变量 camelCase，常量 UPPER_SNAKE |

## 4. Controller 规范

- 一律使用 `@RestController`。
- 跨域由全局 CORS 配置统一处理（由安全组件 `SecurityConfig` 开启，无需每个类加 `@CrossOrigin`）。
- 返回类型统一为 `CommonResult<T>`。
- 请求体使用 DTO，禁止直接暴露 DO/Entity 到接口。
- 需免登录的接口（如登录接口）标注 `jakarta.annotation.security.PermitAll`，由安全组件自动放行。

```java
@RestController
@RequestMapping("/example/hello")
public class ExampleController {

    @GetMapping
    public CommonResult<String> hello() {
        return CommonResult.success("ok");
    }
}
```

## 5. 统一返回 `CommonResult<T>`

所有接口使用 `CommonResult<T>` 包装（位于 `tb-common` 的 `org.example.backend.framework.common.pojo`）：

```json
// 成功
{ "code": 0, "message": "", "data": <T> }

// 失败
{ "code": 500, "message": "错误描述", "data": null }
```

约定：

- `code = 0` 表示成功，`data` 为业务数据。
- `code != 0` 表示失败，`message` 为前端可直接展示的错误描述。
- 提供静态工厂：`CommonResult.success(data)` / `CommonResult.error(code, message)`。
- 全局异常处理器（`@RestControllerAdvice`，**规划待实现**）将统一捕获异常并转为 `CommonResult`。

## 6. 数据库规范

- **PostgreSQL**：`127.0.0.1:5432/tb`（扩展：`uuid-ossp`、`vector`）
- **数据库脚本**：`sql/` 目录下按表拆分，共 17 个 `.sql`：
  - `init.sql`：初始化 `uuid-ossp`、`vector` 扩展（只需运行一次）
  - `vector_store.sql`：pgvector 扩展与向量存储前置（对齐 Spring AI PgVectorStore：1024 维 / hnsw / cosine）
  - RBAC 5 张：`system_user` / `system_role` / `system_menu` / `system_user_role` / `system_role_menu`
  - OAuth2 2 张：`system_oauth2_access_token` / `system_oauth2_refresh_token`
  - 其它：`infra_file`（文件元数据）、`doc_template`（模板生成任务与结果文件）
  - 知识库 4 张：`kb_space` / `kb_document` / `kb_document_parse_block` / `kb_document_chunk`
  - `newsql/`：身份种子数据与数据库全量导出（**仅作参考**，`public.sql` 含 `DROP TABLE` / `DROP TYPE vector`，**禁止在生产库执行**）
- **软删除约定**：`kb_space` 用 `deleted BOOLEAN`；`kb_document` 用 `deleted_at TIMESTAMP`（`NULL` = 未删除）；从属表（`kb_document_parse_block` / `kb_document_chunk`）为**物理删除**，不设软删列。新增表须明确采用其中一种并与同类表保持一致。
- **Mapper**：`@Mapper` 接口 + 注解 SQL，**无 MyBatis XML**；动态语句用 `<script>` + `<foreach>`（如解析块批量插入）。
- **字段映射**：开启下划线转驼峰，`mybatis.configuration.map-underscore-to-camel-case: true`。
- 连接配置放在 `tb-server` 的 `application.yml`，账号密码等敏感信息通过环境变量注入，禁止硬编码。

```yaml
spring:
  datasource:
    url: jdbc:postgresql://127.0.0.1:5432/tb
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
```

## 8. 安全组件

安全由 `tb-spring-boot-starter-security` 提供，基于 Spring Security，采用无状态 Token 认证（JWT 暂未引入）。

- **自动装配**：`SecurityConfig`（`@AutoConfiguration` + `@EnableWebSecurity` + `@EnableMethodSecurity`）与 `SecurityAutoConfiguration`。
- **认证方式**：无状态 Token（`SessionCreationPolicy.STATELESS`），CSRF 关闭，CORS 开启。
- **Token 解析**：`TokenAuthenticationFilter`（`OncePerRequestFilter`）通过 `SecurityFrameworkUtils.obtainAuthorization` 提取 Token（优先 Header `Authorization`，其次参数 `token`，并剥离 `Bearer ` 前缀），当前为占位实现。
- **免登录配置**：`SecurityProperties`（前缀 `tb.security`）提供 `token-header` / `token-parameter` / `permit-all-urls`；接口可用 `@PermitAll` 或 `permit-all-urls` 枚举放行。
- **兜底规则**：`anyRequest().authenticated()`；异步请求（`DispatcherType.ASYNC`）默认放行以支持 SSE。

```yaml
tb:
  security:
    token-header: Authorization
    token-parameter: token
    permit-all-urls:        # 免登录 URL 列表
      - /test/ping1
```

## 9. AI 配置

- AI 模型相关配置（API Key、模型名、超时等）在 `application.yml` 中管理。
- **敏感凭据一律环境变量注入，禁止硬编码**：`application.yml` 中只写 `${VAR}` 占位符，**不提供默认值**（缺失时启动即报错，避免误用弱默认值）。运行时的实际取值来自项目根目录 `.env`（`spring.config.import` 自动加载，见 §10）。
- **文档解析**：`tb.docmind.*` 由 `DocMindProperties` 承载；AK/SK 缺失时启动即失败（`missingCredentials()` 校验）。
- **检索增强**：知识库已有 `searchBySpace`（`VectorStore.similaritySearch` + `spaceId` 过滤），供文档模板生成复用。
- 向量检索依赖 PostgreSQL 的 `vector` 扩展（`CREATE EXTENSION vector`）与 `spring-ai-starter-vector-store-pgvector`（版本 2.0.0-M3）。向量维度固定 1024，与 embedding 模型（`text-embedding-v3`）绑定，**换模型须同步重建向量表**。

> **待整改（现状 / 规范要求）**
>
> | 位置 | 现状 | 规范要求 |
> |------|------|----------|
> | `application.yml` 的对话 / 向量化 `api-key` | 写有明文默认值 `sk-...`，且已入库 | 只写 `${VAR}`，不提供默认值；**已泄露密钥需作废重签** |
> | `spring.datasource.username` / `password` | `postgres` + 空密码 | 改为 `${DB_USERNAME}` / `${DB_PASSWORD}` |

| 变量 | 必填 | 用途 |
|------|------|------|
| `DB_USERNAME` / `DB_PASSWORD` | 是 | PostgreSQL 账号密码 |
| `OPENAI_API_KEY` | 是 | 对话模型（`spring.ai.openai.api-key`） |
| `OPENAI_EMBEDDING_API_KEY` | 是 | 向量化模型（`spring.ai.openai.embedding.api-key`） |
| `MINIO_SECRET_KEY` | 是 | MinIO 密钥（`minio.secret-key`） |
| `DOCMIND_ACCESS_KEY_ID` / `DOCMIND_ACCESS_KEY_SECRET` | 是 | 阿里云文档智能 AK/SK（知识库文档解析，缺失时启动失败） |
| `OPENAI_BASE_URL` / `OPENAI_CHAT_MODEL` | 否 | 有默认值 |
| `OPENAI_EMBEDDING_BASE_URL` / `OPENAI_EMBEDDING_MODEL` | 否 | 有默认值 |
| `MINIO_ENDPOINT` / `MINIO_ACCESS_KEY` / `MINIO_BUCKET` | 否 | 有默认值 |

- **docx-mcp 子进程**：`tb-module-doctemplate` 的 `mcp-servers-config.json` 不再内联任何凭据，由后端进程环境继承 `MINIO_*`；`docx-mcp/config.yaml` 同样只写 `${VAR}` 占位符。

## 10. 启动

**前置：创建项目根目录 `.env`**（已被 `.gitignore` 忽略，不随仓库分发）

```properties
# 项目根目录 .env —— properties 语法；值保持 ASCII，避免反斜杠转义
DOCMIND_ACCESS_KEY_ID=your-ak
DOCMIND_ACCESS_KEY_SECRET=your-sk
# 其余可选变量见 §9 表格
```

`application.yml` 已配置自动加载，从工作目录逐级向上查找，**无需手动 `export`**：

```yaml
spring:
  config:
    import:
      - optional:file:.env[.properties]
      - optional:file:../.env[.properties]
      - optional:file:../../.env[.properties]
```

```bash
cd backend
./mvnw clean install -DskipTests            # 先构建全部模块（含 tb-dependencies BOM）
java -jar tb-server/target/tb-server-0.0.1-SNAPSHOT.jar   # 端口 8086，context-path /api
```

- **Maven 未加入 PATH 时**：使用仓库自带的 `mvnw` / `mvnw.cmd`（首次执行会自动下载 Maven）。
- **只编译单个模块**：`.\mvnw.cmd -DskipTests -pl tb-module-knowledgebase -am compile`。
- 开发模式可直接使用 IDE 运行 `tb-server` 模块的 `BackendApplication` 主类（需在 Run Configuration 中配置环境变量）。
- 测试：`./mvnw test`。
